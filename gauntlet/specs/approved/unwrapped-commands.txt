> 2. Everyone else's Bash runs in bwrap. A PreToolUse hook wraps the command through updatedInput without reading it. agent_type picks the profile.
> - The hook matches these commands exactly, and they run outside the sandbox.

1. Which commands run unwrapped is the project's declaration to make, not the hook's. Hold one payload, `sudo systemctl restart hqplayerd`, and move the declaration: with that text declared under `unwrapped_commands` the payload comes back with no `updatedInput`; with `sudo systemctl restart other` declared instead, and with the key declaring nothing, the same payload comes back wrapped.
   kills: a hook holding the unwrapped set as its own constant unwraps a command no project declared and ignores every command a project does.
   bite: null stub wraps all three payloads and fails the first; a stub holding the set as a constant answers the same under all three declarations and fails the second and third (surface new).
   existing: `tests/test_bwrap_wrap.py:249` `test_only_a_whole_command_that_is_one_pair_subcommand_call_escapes_the_wrap` is the only carve-out test. Its four payloads are all spellings of one `scripts/pair.sh` call, and it never varies `DECLARATION` at `tests/test_bwrap_wrap.py:54`, so it pins no declared command and no declaration key.

2. A declared command matches by the whole string and nothing less. Hold the declaration of `sudo systemctl restart hqplayerd` and move the payload: that exact text comes back with no `updatedInput`, and a trailing space, ` --now` appended, `; rm -rf state` appended, `cd /tmp && ` in front, and `echo ` in front each come back wrapped.
   kills: a predicate matching by prefix, substring or word split runs `sudo systemctl restart hqplayerd; rm -rf state` outside the sandbox, which hands a wrapped shell the one route out by appending text to a declared string.
   bite: null stub wraps all six payloads and fails the first (surface new).
   existing: `tests/test_bwrap_wrap.py:249` pins whole-string matching for the `scripts/pair.sh` carve-out through `_carve_out` at `:228`, with the passthrough, appended, prefixed and wrong-argument cases. Every payload it varies is a `scripts/pair.sh` call and its `DECLARATION` never names an unwrapped command, so it observes the wrap answer for a command no project declared and says nothing about one that a project does.

3. A path a declared command reads is read-only inside a wrapped profile, over the writable set the profile otherwise grants. Hold one probe, `printf x > probe.txt` at the repository root under `prosecutor` with `probe.txt` already on disk holding `y`, and move the declaration: with a declared command whose `reads` names `probe.txt` the file still holds `y` after the run, and with the same command whose `reads` names `other.txt` it holds `x`.
   kills: binding `reads` before the writable binds, or leaving them out, lets a wrapped shell rewrite the file a declared command opens, so the one command that runs outside the sandbox does whatever the shell inside it wrote.
   bite: null stub leaves `x` under both declarations and fails the first (surface new).
   existing: `tests/test_bwrap_wrap.py:219` `test_a_write_under_the_replacement_lands_by_path_and_by_caller` runs a write under the returned invocation through `_write_outcome` at `:192` and pins `probe.txt` at the root as `written` for that same caller. It separates by path and by `agent_type` alone, and its helper unlinks the target before the run, so it cannot observe a pre-existing file surviving; this line holds path and caller fixed, names the file present as part of the input, and separates by the declaration.

4. A `reads` entry naming a path that does not resolve voids the declaration rather than binding what it can. Hold the payload `scripts/deploy.sh --once` and the declaration of a command of that same text with `reads: ["scripts/deploy.sh"]`, both byte-identical, and move the checkout: with no `scripts/deploy.sh` on disk the payload comes back wrapped, and with that file created in the same checkout it comes back with no `updatedInput`.
   kills: a profile binding `reads` with `--ro-bind-try` and no check at declaration skips the unresolvable entry in silence, leaves its directory writable, and still runs the command unwrapped — the project holds a guarantee the mount table does not make, and holds it exactly where a typo put it.
   bite: null stub wraps in both checkouts and fails the second (surface new).
   existing: `tests/test_tests_config.py:383` `test_a_value_that_is_not_a_string` is the comparable case: an unusable value voids the declaration, observed through `_config_lines` over the three directory keys of `DEFAULTS` at `tests/test_tests_config.py:55`. It reaches no unusable shape but a wrong type and an overlapping name, and it observes the void in the reader; this line's unusability is a path that is absent, and it observes the void in the wrap answer, so an implementation passing one can fail the other.
