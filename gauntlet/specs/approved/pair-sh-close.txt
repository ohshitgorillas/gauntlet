brief:
> Last open item of briefs 1-3 in gauntlet/plans/approved/bash-sandbox.txt: `pair.sh close <slug>`.
> `close <slug>` removes a worktree and prints `CLOSED <path>`, or `REFUSED <path> <reason>` where the tree has uncommitted work, since a `close` that discards a red run silently is worse than no subcommand.
> The verb takes the shape `impl checkout|merge <slug>` already has: `close <slug>` removes the spec tree, `close impl <slug>` removes the implementation tree, one path per call.

1. The first field of the stdout of `pair.sh close <slug>` run against a spec worktree with no uncommitted change differs from the first field of the stdout of the same command run against a spec worktree holding an uncommitted change to a tracked file: `CLOSED` against the clean tree, `REFUSED` against the dirty one.
   kills: a `close` that reports the same outcome whatever the tree holds, so a caller cannot tell a round that closed from one that was refused.
   bite: HEAD prints nothing on stdout at either input, prints `usage: pair.sh open|red|merge <slug> | restore <slug> <rev> | impl checkout|merge <slug>` on stderr, and exits 2. `out=$(scripts/pair.sh close pair-sh-restore 2>/tmp/e); echo "stdout=[$out] rc=$?"` -> `stdout=[] rc=2`, and the same after `echo x >> .claude/worktrees/pair-sh-restore-spec/README.md`.
   existing: none, `grep -rn "close\|CLOSED\|REFUSED" tests/` -> three hits in tests/test_cite.py:354-366, all the word `closer` in a bracket-pair fixture, none about pair.sh

2. The set of paths `git worktree list --porcelain` reports after `pair.sh close <slug>` run against a clean spec worktree is the pre-call set with that tree's path removed and nothing else changed, while the set reported after the same command run against a spec worktree holding an uncommitted change to a tracked file equals the pre-call set.
   kills: a `close` that prints its line and removes nothing, or one that removes a tree with uncommitted work in it and discards a red run that exists nowhere else.
   bite: HEAD leaves the set equal to the pre-call set at both inputs. `before=$(git worktree list --porcelain | grep '^worktree ' | sort); scripts/pair.sh close pair-sh-restore >/dev/null 2>&1; after=$(git worktree list --porcelain | grep '^worktree ' | sort); [ "$before" = "$after" ] && echo "set unchanged" || echo "set changed"` -> `set unchanged`
   existing: none, same grep as line 1

3. At `pair.sh close <slug>` and at `pair.sh close impl <slug>`, each run with both trees of `<slug>` present and clean, the second field of the call's stdout is the one path that is in the pre-call `git worktree list --porcelain` set and absent from the post-call set.
   kills: a `close` that prints a path it did not remove — a fixed printer keyed on the arguments, or a `close impl` that prints the implementation tree's path while removing the spec tree.
   bite: HEAD prints nothing on stdout at either call and removes nothing, so there is no path on stdout and no path missing from the post-call set. `before=$(git worktree list --porcelain | grep '^worktree ' | sort); out=$(scripts/pair.sh close impl pair-sh-restore 2>/tmp/e); after=$(git worktree list --porcelain | grep '^worktree ' | sort); echo "stdout=[$out]"; [ "$before" = "$after" ] && echo "set unchanged"` -> `stdout=[]` / `set unchanged`
   existing: none, same grep as line 1

4. The set of paths `git worktree list --porcelain` reports after `pair.sh close impl <slug>` run with both trees of `<slug>` present and clean is the pre-call set with the implementation tree's path removed and the spec tree's path still in it.
   kills: a `close impl` that removes the spec tree, or both, so closing the implementation half of a round destroys the tree the tests were written in.
   bite: HEAD leaves the set equal to the pre-call set. Same command as line 2 with `close impl pair-sh-restore` substituted -> `set unchanged`
   existing: none, same grep as line 1
