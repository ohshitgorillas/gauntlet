## What the owner sees change

The owner states a sweep scope in a brief, in their own words. The auditor prints a target list first — one `<tests dir>/<file>::<test>` per line — then one row per target. The owner sees what was swept before reading any finding.

Rows carry no argument. `STRIKE` and `AMEND` each name a `docs/testing.md` rule number and quote the offending assertion out of the test file; `AMEND` adds one line naming the behavior the test pins. Everything else is `VALID`. A fact the auditor could not read is `NOTE`, never a finding.

Rows are not a route. The owner reads the target list and the rows and says which rows go; only then does the main agent fold `STRIKE` rows into `motion: strike` blocks and `AMEND` rows into `motion: amend` blocks, one block per kind per file, each walking the tests-only lane as a hand-drafted block does today.

Two constraints the fold obeys rather than changes, both pre-existing:

- A mixed block is rejected — `agents/arbiter.md:80`, "Mixed block under". Hence one block per motion kind, which is the owner's grouping.
- An amend block caps at four `replace:` lines — `docs/testing.md:110`, "Four-line cap count". A file with five `AMEND` rows folds into two blocks, not one. Per-file grouping is a floor, not a ceiling.

Per-file grouping is the owner's instruction and not a constraint the tree imposes: `scripts/strike-diff.py:219` names every file any line in the block names, so a two-file block draws no `UNNAMED` from it.

## What it costs

One slug per block. A sweep with findings in five files is five slugs, each with its own `arbiter` round, `scrivener` run and `${CLAUDE_PLUGIN_ROOT}/scripts/pair.sh merge`. Cost scales with files touched, not with rows.

Two blocks over the same file run one after the other, never concurrently: both land in that file, and the second block's base has to hold the first block's landing or its targets read as already gone.

`tests/` cases for the new `BLIND` member are not the main agent's to write. `CLAUDE.md:54` is the rule — "A write to `tests/` from the main agent comes back denied" — so those cases arrive through an approved block and the `scrivener`, after this plan lands. The two `--self-test` files sit in `hooks/`, not `tests/`, so they move in the implementation pass itself.

Every row is judged from the test file alone. A rule 4 or rule 13 finding rests on what a fake speaks to — `docs/testing.md:17`, `docs/testing.md:61` — and where that wire fact lives in `<source dir>/` the row is a `NOTE` and not a finding. Blindness buys the sweep its standing and pays for it here.

`VALID` by default means a missed violation is silent. The sweep is a floor under the suite, never a proof it is clean.
