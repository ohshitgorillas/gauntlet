## What is wrong

There is no way to turn the gauntlet off, and there is no way to ask for one that the chain itself will not treat as an attack.

Every gate in this repository is a `PreToolUse` denial with no escape. `.claude/settings.json:4-24` wires `specs-lane.py`, `plans-lane.py`, `tests-lane.py` and `verdicts-lane.py` session-wide, `.claude/settings.json:26` adds `reviews-lane.py`, and each denies at the tool call with no condition but the caller's `agent_type` — `.claude/hooks/plans-lane.py:76` is the shape, and the other six repeat it. `verdicts-lane.py --stop` at `.claude/hooks/verdicts-lane.py:157` goes further and refuses to end a turn. The set is deliberate and the repository argues for it at length; what it does not have is an owner-side switch, so a session that wants to do something outside the chain — repair a corrupted lane file, demo the repo, bisect a hook against its own history, work on the hooks themselves — has to weaken a hook to do it, which `CLAUDE.md:31` names as the one thing that must not happen: "The lane hooks stay on and unweakened."

That leaves the owner with two bad moves and no good one. Comment out a matcher in `.claude/settings.json` and restore it afterwards, which is the shape `CLAUDE.md:31` forbids by name and which leaves the repository one forgotten `git checkout` away from shipping with a gate off. Or run the work somewhere the hooks are not wired, which means the hooks are not exercised on the work that touched them.

The second half of the defect is that any switch built naively makes the situation worse rather than better. A bypass an agent can reach for is not a bypass, it is a hole: the agent that wants a write through the lane is exactly the agent that would set the variable. And a bypass that is read anywhere but the entry point of a hook silently disarms that hook's own `--self-test`, which is the repository's stated bar at `CLAUDE.md:25` — "A hook change that passes `pytest` and fails its own `--self-test` is exactly what this bar catches." A self-test that can be switched off by an environment variable catches nothing.

## What the owner sees change

`GAUNTLET=off claude` starts a session with the seven lane hooks silent and the `Stop` gate silent. Nothing is denied that the tool would otherwise allow, no turn is blocked for an unruled red run, and the artifacts in `gauntlet/` are writable by any hand including the main agent. `claude` with the variable unset, empty, or set to anything but `off` denies and allows exactly what this repository denies and allows today: every hook fires, on the same matchers, with the same verdicts. It is not byte-for-byte the session it is today, and the difference is deliberate — `--prompt` runs on every turn of every session, so a gauntlet-on session gains the never-propose rule in its context and `--bash` gains two denied command shapes that nothing legitimate in this repository uses.

A bypassed session says so, twice. Once at start, as a banner naming what is off. Once per prompt, as a standing line in the agent's context, so that thirty turns in the agent does not assume it is working under a chain that is not running.

A session with the gauntlet on also says something, once per prompt: the agent may never propose the bypass, never set the variable, and never suggest the owner set it. That rule has no exception and no cost/benefit case attached to it, because a rule an agent can argue its way past is a rule the agent will argue its way past on the one turn it matters.

And a session with the gauntlet on cannot reach the switch. A Bash command carrying a `GAUNTLET=` assignment is denied, and so is a nested `claude` invocation. The bypass belongs to the hand that launches the session and to no hand inside it.

## Which files get touched, and roughly how

**`.claude/hooks/shell_shapes.py`, one new function.** `bypassed()`, beside `deny()` at `.claude/hooks/shell_shapes.py:613`, reading `os.environ` and nothing else — `os` is already imported at `.claude/hooks/shell_shapes.py:43`, so the function is three lines. The read is strict: the hook payload is never consulted, because the payload is the one input an agent controls, and a `bypassed()` that honoured a payload key would be a bypass any subagent could forge in a tool call. Comparison is against the exact value `off` after strip and lowercase, so an unset, empty or misspelled variable leaves the gauntlet on, which is the safe direction.

The module docstring, which ends at `.claude/hooks/shell_shapes.py:37`, gains the reason: this module is the one place all seven hooks already share, so the switch is defined once and each hook reads it rather than each hook parsing an environment of its own.

**The seven hooks, one guarded line each.** `sh.bypassed()` returns at the top of `main()`, before the payload is read: `.claude/hooks/specs-lane.py:84`, `.claude/hooks/plans-lane.py:88`, `.claude/hooks/tests-lane.py:109`, `.claude/hooks/reviews-lane.py:164`, `.claude/hooks/verdicts-lane.py:110`, `.claude/hooks/no-impl-reads.py:396` and `.claude/hooks/blind-bash.py:104`. Nowhere else. `_verdict()` at `.claude/hooks/plans-lane.py:76`, `.claude/hooks/verdicts-lane.py:98` and its five siblings is untouched, and every `self_test()` in the repository calls `_verdict()` directly rather than going through `main()`. That is what keeps the self-tests honest, and it is the whole reason the guard goes where it goes: `check-gates.sh` run inside a bypassed session still reports the truth about what the hooks decide.

**`verdicts-lane.py --stop`, guarded at the dispatch rather than inside `stop()`.** This is the one place the brief's letter cannot be followed, and the brief's own reason is why. `stop()` at `.claude/hooks/verdicts-lane.py:157` is both the `--stop` entry point and the decision function: four of `self_test()`'s lines reach it directly against a temporary tree — lines 3, 4 and 5 through `gate()` at `.claude/hooks/verdicts-lane.py:201-204`, and line 7 by calling `stop(...)` at `.claude/hooks/verdicts-lane.py:276`. Line 6, at `.claude/hooks/verdicts-lane.py:270`, goes through `slugs()` to `_complaints()` and never calls `stop()`. A guard inside `stop()` would therefore make four self-test lines pass vacuously in a bypassed environment — precisely the dishonest self-test the brief's "never in `_verdict()`" clause exists to prevent, and four is what the docstring at `.claude/hooks/verdicts-lane.py:167` already counts: "the `--stop` gate's four states". So the guard goes on `.claude/hooks/verdicts-lane.py:306`, `sys.exit(stop()) if "--stop" in sys.argv else main()`, and it goes there rather than earlier in the block so that the `--self-test` branch at `.claude/hooks/verdicts-lane.py:304-305` is reached first and is never gated on the environment at all. `stop()` and `_complaints()` stay pure.

**`.claude/hooks/gauntlet-off.py`, new, three events and a `--self-test`.** One file rather than three, because all three behaviours are the same one-line question asked of the same variable, and splitting them would put three copies of that question in the tree.

- `--session-start`, a `SessionStart` hook. Silent when the gauntlet is on. When off, a banner naming what is not running: the seven lane hooks by name, the `Stop` gate, and the plain statement that nothing in `gauntlet/` is protected from any hand.
- `--prompt`, a `UserPromptSubmit` hook, which emits on every turn either way. Gauntlet on: the never-propose rule, stated absolutely. Gauntlet off: the standing notice that the chain is not running, so the banner is not the only thing keeping the state in view thirty turns deep.
- `--bash`, a `PreToolUse` hook, live only when the gauntlet is on and silent when it is off. It joins the existing `Write|Edit|NotebookEdit|Bash` block rather than taking one of its own, so it is handed three tool names it has no opinion about; its first test is `tool_name`, returning silently on anything but `Bash`, the way `.claude/hooks/blind-bash.py:97` does it. Sharing the block keeps the seven lane hooks and this one in one list, where a reader sees at a glance what a tool call passes through. It denies two command shapes, and neither test is a substring search over the command text. The assignment test is for a `GAUNTLET=` word: a leading assignment on a segment, an `export` or `set` argument, or an `env` argument. The `claude` test is on the head word of a segment, taken from `segments()` at `.claude/hooks/shell_shapes.py:231` and `words_of()` at `.claude/hooks/shell_shapes.py:437`, after any leading assignments and any wrapper — `env`, `nohup`, `timeout`, `xargs` — are stepped over. A head-word test rather than a text match because the commands this repository documents carry the string `claude` inside a path: of the nine checklist lines at `README.md:71-79`, seven are `python3 .claude/hooks/<name>.py --self-test`, starting with `README.md:71`, and the remaining two name `scripts/`. Matching text would deny the repository's own documented commands; matching the head word denies `claude -p ...`, `env GAUNTLET=off claude` and `nohup claude` and lets every `.claude/` path through. The reading it gives up is a `claude` reached through a shell it cannot see into — `bash -c 'claude'`, a wrapper script named something else — which is the same bound every other shape test in `shell_shapes` carries.

Both halves of the denial are needed and neither is redundant. A bare `GAUNTLET=off` prefix on a shell command does not in fact disarm anything: hooks run in the Claude Code process's environment, not in the environment of a `Bash` tool call. `ASSUMED` — that is harness behavior and nothing in this tree settles it; the measurement is one bypassed session and one `GAUNTLET=off echo` under a live one, and the denial is correct either way. It is denied because the combination that does work is `GAUNTLET=off claude`, and denying the two halves separately means no spelling of the pair gets through — an `export` on one line and a bare `claude` on the next, an `env GAUNTLET=off`, a `claude` behind `nohup` or `timeout`.

`scripts/gates/check_md_trivia.py:221` shells out through `binary("claude")` and is not affected by the `--bash` denial. The mechanism is that it is a Python `subprocess.run` inside that script rather than a `Bash` tool call, and a `PreToolUse` matcher sees tool calls only. Nothing about where the script is wired is load-bearing for that, and `.claude/settings.local.json` in fact carries one `PostToolUse` entry, for `md-softwrap.py`, and no trivia entry at all.

## What it costs

**An eleventh gate and a re-copy for every consumer.** `README.md:71-79` grows a line, `CLAUDE.md:23` grows a name, and `CHANGELOG.md:17` carries the same breaking note it has carried for each round of this shape.

**The suite inherits the variable, and that is the sharp edge of this change.** `tests/test_hook_wire.py:52` runs each hook as a subprocess with no environment argument, so the child inherits the session's environment; `payload_decision` at `tests/test_blind_reads_declaration.py:156` does the same, and `hook_decision` at `tests/test_blind_reads_declaration.py:127` is a wrapper over it, so the scrub lands in the former. Every deny-asserting case in both files — `DENY` at `tests/test_hook_wire.py:46` and `tests/test_blind_reads_declaration.py:57` — would pass vacuously in a bypassed session, and the suite would be green while proving nothing. The fix is to scrub `GAUNTLET` from the child environment in both helpers, the way `scripts/gates/check_md_trivia.py:218` scrubs `CLAUDECODE` from its own subprocess environment. This is not optional polish: shipped without it, this change converts the repository's own test suite into something that lies under exactly the condition it was added to describe. It is a `tests/` write, so it is the `gauntlet-scrivener`'s, through a spec block, and it should be the first block after this plan rather than a later one.

`check-gates.sh` closes the same hole from the other side at `scripts/gates/check-gates.sh:44`, and that half is the main agent's because the script is not under `tests/`. The two fixes are not redundant: the script protects the gate run, the helpers protect a bare `pytest`.

**A bypassed session that runs the chain anyway produces artifacts worth nothing, and nothing stops it.** The switch silences the hooks; it does not stop `scripts/pair.sh`, and it does not stop a `gauntlet-arbiter` or a `gauntlet-scrivener` being spawned. Under bypass a blind subagent is not blind: `no-impl-reads.py` returns silently, so it can read the implementation it is meant never to see, and `blind-bash.py` returns silently, so `scripts/blind.sh` stops being its one command and every shell shape is open to it — the `bwrap` confinement inside `blind.sh` still applies to what runs through `blind.sh`, and nothing routes anything through `blind.sh` any more. An approved spec block written in such a session was reviewed by an agent that could read the code, and a test written in one may mirror the implementation; both land in tracked files indistinguishable from ones produced under the chain. The mitigation is the banner and the per-turn notice and nothing else, which is why the notice repeats every turn rather than once. The chain is for work done under the chain, and a session that turns it off should not run it.

**The switch is exactly as strong as control of the environment, and no stronger.** Anyone who can set a variable in the shell that launches `claude` can turn the whole chain off. That is the feature, stated plainly rather than defended: the gauntlet is a discipline the owner imposes on agents, not a sandbox that contains a hostile one. The `--bash` denial raises the floor by keeping the switch out of reach of the agent inside a running session, and it does not and cannot make the switch unreachable to the hand that starts the session.

**A bypassed session leaves no trace on disk.** The banner and the per-turn reminder are context, not artifacts; nothing in `gauntlet/` records that a session ran unguarded, and a file written into a lane by the main agent under bypass is indistinguishable afterwards from one the reviewer wrote. A tracked marker was considered and left out: it would be a new artifact kind, and the artifact kinds are the owner's call rather than a side effect of a switch. Named here as a known gap, not as work this plan defers.

**The never-propose rule costs a `UserPromptSubmit` call on every turn of every session**, bypassed or not — a few hundred bytes of context per turn and no subprocess beyond the hook itself. That is the price of the rule surviving a long session, which a one-time `SessionStart` injection does not.

Deliberately left out, in the owner's words: "the markdown gates and the host change-budget hook". `md-softwrap.py` and `check_md_trivia.py` stay live under bypass, and so does `~/.claude/hooks/command-burst-guard.py`, which is user scope and outside this repository in any case.
