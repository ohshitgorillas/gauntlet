## What is wrong

A plan's citations are typed by hand, and nothing checks them.

`docs/plans.md:37` requires them — "A claim about the tree carries `file:line`" — and `docs/plans.md:46` says where they come from: "The pointers a plan cites come from one `gauntlet-detective` round: every question in one brief, a `file:line` table back." Between that table and the plan prose sits a retyping step with no check on it. The approved plan on disk, `docs/gauntlet/plans/juror-verdicts-lane.txt`, carries on the order of fifty citations, most of them bare continuations; every one was typed from a table or from memory.

The tree is frozen while a plan is drafted and reviewed, so a citation that does not resolve is a transcription error and nothing else. That is what distinguishes the class from the judgment the prosecutor's check (b) exists for, and it is what makes a script the right instrument: the whole class is decidable without reading a sentence.

Nothing in the repo does this today. No script parses a `file:line`, resolves one, or reads a plan file's contents at all: `docs/gauntlet/plans` appears in `.claude/hooks/plans-lane.py`, `.claude/hooks/reviews-lane.py`, `.claude/hooks/specs-lane.py:123` and `.claude/hooks/no-impl-reads.py` only as a path to gate writes and reads against. `scripts/excision-diff.py` parses a spec block with `_LINE` and `_FIELD` at `:38-39`, and those regexes match `N. excise <target>` lines, not citations.

This plan's first draft carried a second defect — that the `gauntlet-prosecutor` cannot run a script in `scripts/`, because `.claude/hooks/reviews-lane.py:143` denies the reviewers every writing `Bash` command and `shell_shapes.py:317` classifies `python3 <script>` as one. That is still true of the tree and it is no longer a defect of this plan, because nothing here asks the prosecutor to run anything. It is recorded because the first draft proposed widening that lane, and a reader comparing drafts should find the reason the widening went away rather than infer one.

## What the owner sees change

A plan's citations resolve before a reviewer or the owner reads it.

One command before handing a draft over: `--check` exits 1 and names every citation that does not resolve, by shape — `MISSING` for a path that is not there, `RANGE` for a span running past the end of the file, `AMBIGUOUS` for a basename matching more than one path, `ORPHAN` for a bare number with nothing to inherit a path from, and `QUOTE` for a number pointing at a line that does not contain the text the plan quotes. Each failing row prints the citation as written, the path it resolved to, and the line it found.

Two classes of row print whether or not they fail, and they are the reason `--check` is not a silent-on-success command. A bare continuation prints `INHERITED-FROM <file>`, always. A citation resolving outside the checkout prints `CROSS-REPO <file>`, always. Neither is an error and neither sets the exit code; both are cases where the script resolved something the author cannot see in the text they wrote, and the whole of the guarantee for them is "this is where it landed". A run with no failures and no rows at all means every citation was a plain in-tree one — and on a plan written the way this repo writes them, that run does not occur. Bare continuations dominate: the approved plan on disk is mostly `` `:49` ``-shaped, so `INHERITED-FROM` rows are the normal output, not a warning. The `--help` text has to say so, because a command that prints a screen of rows on a clean document is read as failing unless its own documentation says otherwise, and an author who reads it that way will stop running it.

For the author, `--fix` fills a number from a quoted anchor where the anchor matches exactly one line, and refuses on zero matches or several. It never guesses, and it never rewrites a number that already resolves.

For the `gauntlet-prosecutor`, its check (b) round changes in one way only: the numbers resolve when it opens them. `.claude/agents/gauntlet-prosecutor.md:59` is check (b), "Grounding", and its instruction is "Open each citation, compare against what plan says it shows". It still opens each one. What stops arriving is the finding raised on a number that was simply mistyped. On the plan this script was drafted against, that was one failing check line in nine across two rounds, carrying two miscitations — the full count and the eight it excludes are under "Open questions", and the ratio is given there rather than here because a round-1-only reading of it flatters the script. The prosecutor runs nothing, reads nothing new, and takes no instruction from this plan.

What (b) keeps is everything the brief names as residue: a wrong line quoted accurately, right text sitting in a dead branch or a comment, a quote cherry-picked where the next line reverses it, a sentence that overstates what its line says. Those are relevance. They need the lines around the cited one, which no resolver row carries, and `.claude/agents/gauntlet-prosecutor.md:23` — "Prefer reading cited line over reasoning about what it probably says" — stands exactly as written.

## Which files get touched, and roughly how

**`scripts/cite.py`, new.** Modeled on `scripts/excision-diff.py`, the repo's only existing report-and-exit script and the closest shape by construction: module constants and regexes at `:36-39`, a parsed-line dataclass at `:42-57`, a parser at `:60-77`, per-item verdict functions at `:119-141`, a `report` assembler at `:144-154`, an argparse `main` at `:157-170`, a `self_test` at `:173-219`, and the single dispatch line at `:222-223`, `sys.exit(self_test() if "--self-test" in sys.argv else main(sys.argv[1:]))`. `cite.py` takes that skeleton with two mode flags in place of `--spec`/`--base`/`--head`.

The parser is the work. The grammar it accepts, in the order the brief names it:

- a full citation, path and number inside backticks: `` `docs/plans.md:37` ``;
- a range: `` `:202-203` ``, `` `gauntlet-juror.md:8-11` ``;
- a bare continuation, a number with no path: `` `:49` ``, which inherits the path of the nearest preceding full citation in the same document, and always prints `INHERITED-FROM <file>`, passing or failing, so a reader sees which file it landed in;
- a basename with no directory: `` `pair.sh:86` ``, resolved against the tree, `AMBIGUOUS` where more than one path matches;
- a cross-repo path, one resolving outside the checkout: not `MISSING`, since `/home/atom/dev/CLAUDE.md` is a real file and a legitimate citation from a plan in this repo.

Five boundaries of that grammar, each with a reading rather than a silence:

- **A cross-repo citation.** It resolves — path and line are checked the same way — and it prints `CROSS-REPO <file>` on a row of its own whether or not it fails, because it is the one citation class the frozen-tree argument does not cover. `/home/atom/dev/CLAUDE.md` is outside this checkout, nothing in this repo's chain freezes it, and a number correct when it was typed can go stale without any edit here. So the reading is: checked like any other, never `MISSING` for being outside, exit code unaffected, and always visible in the output so the author knows a citation rests on a file this repo does not control.
- **A continuation with nothing to inherit from.** A bare `` `:49` `` with no full citation before it in the document — the first citation in a file, or one whose antecedent was cut in an edit — is `ORPHAN`, and `--check` exits 1 on it. It cannot be a quote mismatch, because there is no file to open, and it must not be silently skipped: an orphan is the exact shape a prose edit produces when it removes the sentence that carried the path.
- **A continuation that inherits the wrong file.** This is the brief's own second error shape, "bare `:49` inheriting the wrong file", and it is the one the script cannot decide: a `` `:49` `` that inherits the wrong path, lands on a line that exists, and carries no quoted anchor is indistinguishable to the script from a correct one. Nothing here detects it. What the script does instead is refuse to hide it — every bare continuation prints `INHERITED-FROM <file>`, passing or failing, so the author reads back which file each number landed in and sees a wrong inheritance as a wrong filename rather than as silence. A quoted anchor turns the case decidable, and where the plan has one it is `QUOTE` like any other mismatch.
- **A range against the quote rule.** A range passes when any line in the span contains the quoted text, not when the first does and not when all do. Any-line matches how ranges are actually cited — `` `:202-203` `` names a two-line construct and the sentence quotes one of them — and first-line or all-lines would fail citations that are correct. The span is still checked against the file's length, so `RANGE` still fires on one running past the end.
- **A citation with no quoted text.** Most citations in a plan are structural: `` `:58` `` naming where a function starts, with no quotation beside it. The quote rule has nothing to test, so the reading is existence only — the path resolves and the number is in range — and `--check` does not exit 1 on it. This is the majority case, not an edge, and it is where the guarantee is thinnest: for these the script says the line exists and nothing whatever about whether it says what the plan claims.

A number in prose without backticks is out of scope, by the owner's sentence. That is what keeps the parser decidable: the backticks are the delimiter, so "line 72 now says six" is prose and `` `:72` `` is a citation.

**`docs/plans.md`.** The bare continuation is not documented anywhere in the repo. `docs/plans.md:37` and `:46` are the only two lines stating how a citation is written, and neither mentions ranges or the continuation form; an exhaustive grep across `docs/`, `.claude/agents/`, `README.md` and `CLAUDE.md` finds the `file:line` convention named at `.claude/agents/gauntlet-detective.md:3`, `:24`, `:41`, `:52` and `:60`, at `.claude/agents/gauntlet-arbiter.md:52`, `:110`, `:163` and `:181`, at `.claude/agents/gauntlet-prosecutor.md:23` and `:41`, and at `README.md:23`, and no line anywhere describing a citation that omits its path.

Meanwhile the one approved plan on disk uses the form throughout. The convention is live and unwritten, and a script that pinned it would be enforcing a grammar the repo never stated. `docs/plans.md` takes the grammar — the five forms and what a bare number inherits — as prose, in the section carrying `:37`. The script then checks a documented rule rather than inventing one.

**`.claude/hooks/no-impl-reads.py`: no change, and the blind-agent exclusion holds without one.** The brief names `reviews-lane.py` as the enforcement point. It is not: `reviews-lane.py` gates the reviews lane and knows nothing about `scripts/`. The hook that holds the exclusion is `no-impl-reads.py`, and it already does, three ways over.

## What it costs

A ninth gate on a bar that reads "all eight", an eighth line on the consumer's list, and both re-counted by every consumer who tracks them.

A grammar the repo now has to hold. Writing the continuation form into `docs/plans.md` turns a convention into a rule, and a rule has an enforcement cost: a plan that omits a path where the script expects one starts failing a check no plan has ever failed. The five forms and the five boundaries have to be settled in the first version rather than as each first bites, which is why both lists are in this plan rather than in the implementation.

**The frozen-tree assumption, which is the argument for the whole script.** It holds for the main checkout and not for a worktree: `.claude/worktrees/<slug>-spec` and `-impl` are live during the implementation stage, and `shell_shapes.py:397-400` treats them as roots by construction. The script resolves its root the way the repo's existing gates do, from its own path rather than from the cwd — `scripts/gates/check_md_trivia.py:63` is `ROOT = Path(__file__).resolve().parent.parent.parent` — so each checkout checks its own copy of a plan. A plan citing the main checkout while being checked from inside a worktree is the case that produces a false `MISSING`, and it is named here rather than discovered.

**A citation that resolves and lies.** `--check` passing is not a claim that the plan is grounded. The guarantee is the brief's and it is one sentence: the number points at a line containing that quote. A green `--check` on a plan whose every sentence misreads its line is a plan that has passed nothing, and check (b) is what stands between that plan and the owner. Worth stating in the script's own `--help`, because a tool reporting `OK` is read as an endorsement whatever its documentation says.

**An uncited claim.** `--check` sees citations. A load-bearing claim carrying no citation at all is invisible to it, and that is the failure check (b) names first: "claim with no citation and no `ASSUMED` tag unresolved on its face", at `.claude/agents/gauntlet-prosecutor.md:59`. The one class of grounding defect a plan gets no help on is the one where the author never typed a number. Nothing here changes that.

**`--fix` writes into the document it reads.** Against a draft under `docs/gauntlet/drafts/plans/` that is the main agent's own file and nothing gates it. Against anything under `docs/gauntlet/plans/`, `.claude/hooks/plans-lane.py` denies every hand but the prosecutor, so `--fix` on an approved plan fails at the tool call. That is correct and wanted: an approved plan is the artifact a later stage reads, and a script that could rewrite its numbers after approval would defeat the lane.

Deliberately left out, each by an owner sentence: `--resolve` and the reviewers'-lane allowance it required; any per-turn re-check of a filled number; any resolver for prose numbers without backticks; and any verdict vocabulary in the output.
