## What is wrong

Every lane hook decides a `Bash` call by reading the command string. `shell_shapes.py` is the reader: `segments` at `.claude/hooks/shell_shapes.py:201`, `words_of` at `:309`, `has_inline_script` at `:241`, `is_runner` at `:262`, `git_write_form` at `:324`, `segment_writes` at `:344`, `command_writes` at `:363`, `lane_write_in` at `:396`. Four hundred of its 497 lines exist to answer one question about a string: does this command write.

That question is undecidable on a string, and the repository's own history is the evidence. `docs/gauntlet/specs/shell-shape-classification.txt`, `docs/gauntlet/specs/fail-open-bypasses.txt` and `docs/gauntlet/specs/git-read-subcommands.txt` are three approved blocks, each closing a class of command the classifier read wrong. The last one landed at commit `5494faa` and covered eight git subcommands; `--output` and `git grep -O` came with it. Each round adds a member to a list and leaves the next spelling open: an env prefix, a here-document, a command substitution, a shell function, a `find -exec`, an `xargs`. A classifier that must enumerate the shapes of a Turing-complete language is behind by construction.

This plan was itself denied by that classifier while being written. A heredoc writing this draft to `docs/gauntlet/drafts/plans/` was refused by `reviews-lane.py`, because the prose quoting the owner's brief contains the characters of the reviewers' lane path. `.claude/hooks/shell_shapes.py:422` searches the heredoc body for the lane pattern, so prose about a lane, inside a document being written somewhere else entirely, is a write to that lane.

The blind agents are where the classifier costs most, because there it is the only thing standing between a blind agent and the implementation. `.claude/hooks/no-impl-reads.py:325` opens a branch that walks stages, tracks `cd`, lets a runner through at `:351`, and judges each remaining word by `readable` at `:165`. Two of its escapes are structural. A recognized runner passes without its arguments being read at all, so any interpreter the config names reads whatever it likes. And `cd` tracking gives up on `cd -` and `cd ~...` at `:347`, falling back to the session cwd, which is a guess rather than a fact.

The sandbox escape is not hypothetical on this host. `/run/user/1000` carries `bus` and `systemd`, so a command that reaches the session D-Bus can ask `systemd --user` to start a unit, and that unit runs outside anything the calling process was confined by. Nothing in `.claude/hooks/` mentions `/run/user`, and no string classifier can, because the escape is a socket rather than a spelling.

The blindness wiring also disagrees with the agents that depend on it. `.claude/agents/gauntlet-juror.md:4` gives the juror no `Bash`, and `:73` states the reason in the agent's own words. Yet `.claude/agents/gauntlet-juror.md:8` still wires `no-impl-reads.py` at a `Bash` matcher, and five more lane hooks beneath it, for a tool the agent does not hold. The `gauntlet-arbiter` holds `Bash` at `.claude/agents/gauntlet-arbiter.md:4` and its body names no command it needs one for.

The other two blind agents need a fixed set of shapes between them. The `gauntlet-scrivener` runs `git status --porcelain` at `.claude/agents/gauntlet-scrivener.md:60`, the suite at `:75` and `:76`, and five mechanical gates at `:102`. The `gauntlet-bailiff` runs one `git show` of a committed spec at `.claude/agents/gauntlet-bailiff.md:53`. All fixed, all parameterized by a file path, a slug or a commit — and to serve them the repo carries a general-purpose shell classifier.

`scripts/pair.sh` already owns every git step that writes a lane file, but only for three of them: `cmd_open` at `scripts/pair.sh:65`, `cmd_red` at `:82`, `cmd_merge` at `:106`, dispatched at `:146`. The steps it does not own — restoring a lane file from an object, cutting and merging the implementation tree, removing a worktree — are typed as raw git by the main agent, which is why `docs/approved-specs.md:52` has to carve `git restore --source` out of the classifier by hand.

## What the owner sees change

No hook reads a `Bash` command string to decide what it does. A command either matches one of a closed set of whole-string patterns and runs unwrapped, or it is wrapped unread and runs inside `bwrap`.

For the four blind agents, `Bash` stops being a general tool. The `gauntlet-juror` and the `gauntlet-arbiter` lose it entirely, matching what `.claude/agents/gauntlet-juror.md:73` already says. The `gauntlet-scrivener` and the `gauntlet-bailiff` keep one command, `scripts/blind.sh`, with the subcommands `test`, `status` and `show`. A blind agent typing anything else is denied by name, not by analysis, and the denial cannot be spelled around.

For every other agent and for the main agent, `Bash` keeps its full surface and loses its reach. The command the agent typed is the command that runs; what changes is what the filesystem looks like from inside it. Everything is readable. Writable is the repository, the session's own scratch directory, and `~/.cache`. Read-only again inside the repository: every lane directory in every checkout, `state/red`, `state/merge`, `.claude/`, `scripts/`, `.git/hooks` and `.git/config`. `~/.gitconfig` is read-only. `/run/user` is masked with an empty tmpfs, which closes the D-Bus route to `systemd --user`.

A write the sandbox refuses reads as an ordinary filesystem error rather than as a hook denial with a paragraph of prose. That is a real loss of explanation, and it is priced under "What it costs".

`scripts/pair.sh` grows from three subcommands to seven: `open`, `red`, `merge`, `restore`, `impl checkout`, `impl merge`, `close`. These run unwrapped, matched whole-string, and they are the only route by which a lane file changes on disk.

The lane hooks keep denying `Write`, `Edit` and `NotebookEdit` by path, and the reviewer read-block keeps firing on `Read` and `Grep`. What they lose is their `Bash` branch, and five files become one table of directory to writer.

## Which files get touched, and roughly how

**`.claude/hooks/bwrap-wrap.py`, new.** A `PreToolUse` hook on `Bash` that returns `updatedInput` with the command wrapped in a `bwrap` invocation and never inspects the string. Claude Code honours `updatedInput` from a `PreToolUse` hook on `Bash`, settled against a live hook rather than assumed: a hook returning `updatedInput` with the command rewritten to `( echo WRAPPED_BY_A ; echo PROBE_MARKER )` produced a run whose output was `WRAPPED_BY_A` then `PROBE_MARKER`, so the rewritten command is the command that ran. The same probe settles three further readings the design rested on, and one of them refutes the shape the plan gave it: every other hook entry receives the original `tool_input`, all three logging `saw=echo PROBE_MARKER` rather than the first hook's rewrite, whether it sits beside the wrapper in the same matcher block, in a second matcher block of the same file, or in a second project settings file; and the entries run in parallel rather than in sequence, with all four start lines falling inside `0.000323` seconds of each other at `1789333393.819007` through `1789333393.819330`, in an order that does not follow the order they are wired in, while the wrapping entry's `a-end 1789333394.819708` lands a full second later across its `time.sleep(1.0)`. Hook entries under one matcher therefore neither chain nor order, and two entries both returning `updatedInput` race, so the carve-out cannot be a second entry: `bwrap-wrap.py` is the only `PreToolUse` entry on `Bash` that `.claude/settings.json` wires, and it asks `pair-passthrough.py` for the carve-out decision before wrapping. Hooks wired elsewhere still run, and the probe settles their dispatch as far as a second matcher block and a second project settings file, both of which saw the unrewritten command. The user-scope file is outside that reach, and item 4 carries the residue. `bubblewrap` 0.12.0 is at `/usr/bin/bwrap` on this host. The profile is chosen by `agent_type`, the same payload field the lane hooks read at `.claude/hooks/plans-lane.py:79` and its four siblings. Three profiles: default; reviewer, whole filesystem read-only plus a tmpfs over the reviewers' own lane; and passthrough for the two blind agents. The blind agents reach this hook like everyone else — `README.md:68` has the session-wide hooks bind every subagent, and `blind-bash.py` denies their other commands without stopping the one it allows — so they get a third profile, passthrough, selected by the same `agent_type` field. `scripts/blind.sh` runs its own `bwrap`, and wrapping a wrapper gains nothing while costing a nested mount setup on the one command those agents have. `--unshare-pid` is taken, and what it buys is narrower than it looks. `bwrap --ro-bind / / --dev /dev --proc /proc --tmpfs /run/user --die-with-parent sh -c 'touch /proc/<outer pid>/cwd/probe'` returns `touch: cannot touch '/proc/428192/cwd/probe-a': Permission denied`; the same command with `--unshare-pid` returns `No such file or directory`. The route out through an outer process's `/proc` entry is closed either way, because that process is outside the sandbox's user-namespace mapping. `--unshare-pid` removes the entry rather than denying it, which is defense in depth against a future kernel or mapping that would make the denial a permission rather than an absence. The wrapper re-lists `.claude/worktrees/*` on every call and binds each existing tree back writable, because the directory itself is read-only and a tree cut since the last call must still be writable. Two cases fall out of that re-listing and are stated rather than left to the reader: no worktrees at all, where the bind list is empty and the wrap still runs; and a tree removed between calls, where a stale bind would fail the `bwrap` invocation outright, so the list is built from what exists at call time and never cached.

**`.claude/hooks/pair-passthrough.py`, new.** The carve-out brief line 22 names. `scripts/pair.sh` writes lane files by design, so it must run unwrapped, and something has to decide that. It is a module rather than a hook entry, holding one anchored whole-string pattern per subcommand with a strict slug argument and exposing a single predicate that answers yes or no for a whole command; `bwrap-wrap.py` calls it and returns no `updatedInput` where it answers yes. It is not a second hook entry ordered before the wrapper, because entries under one matcher run in parallel and do not chain, so an ordered carve-out has no mechanism to mark a call for a hook that has already received the unmodified input and may already have answered. This is the same class of mechanism as `blind-bash.py` — a closed set of anchored whole-string patterns, with nothing to extend as new commands appear — and not the class this plan deletes, which walks a command apart and judges its pieces. Naming it as its own file is the point: a `bwrap-wrap.py` that decided for itself which commands to skip would be a classifier again, under a new name.

**`.claude/hooks/blind-bash.py`, new.** A `PreToolUse` hook on `Bash` wired only from the `gauntlet-scrivener` and `gauntlet-bailiff` frontmatter. ## What it costs

The work is four spec blocks and one plan, not one change. The blind-agent half (brief 1), the sandbox half (brief 2), `pair.sh` (brief 3) and the path-hook fold (brief 4) each land on their own, in that order, because each later one rests on the earlier: the sandbox is what makes the blind agents' loss of general `Bash` survivable, and the path-hook fold is only safe once nothing reads a command any more.

Tests die in bulk. Of the 15 tests in `tests/test_hook_wire.py`, the ones pinning Bash classification are at `tests/test_hook_wire.py:132`, `:184`, `:216`, `:242`, `:275`, `:300`, `:331`, `:424`, `:450` and `:531` — ten, by the grounding round's table. Those pin behavior this plan deletes, so each is a line in a `motion: strike` block, and three approved specs on disk — `docs/gauntlet/specs/shell-shape-classification.txt`, `docs/gauntlet/specs/fail-open-bypasses.txt` and `docs/gauntlet/specs/git-read-subcommands.txt` — describe behavior that will no longer exist. The blocks that replace them pin the mount table instead: a write to a read-only bind fails, a read of a masked path fails, a blind agent's non-`blind.sh` command is denied by name.

`CLAUDE.md:31` is overturned deliberately, not quietly. Every lane hook's `Bash` matcher goes, which is the narrowing that sentence forbids. The rule's reason survives — a hook is not disabled to land a change — and the sentence is rewritten to say that a lane's shell half is held by the sandbox rather than by a matcher. An owner who reads that rewrite as a weakening should say so, because nothing in the tree will.

The denial message is the other real loss.
