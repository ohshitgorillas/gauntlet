## What is wrong

No writing formatter in the blind shell. `scripts/blind.sh:171` runs `black --check`, check mode only, and `hooks/blind-bash.py:106-110` admits three subcommands, none of which writes. Scrivener sees `FAIL black`, cannot reformat, reports the failure up. Main agent re-requests.

No rule making the failure the scrivener's. `agents/scrivener.md:93` says the run "runs the tests you wrote and the mechanical gates that apply to them" and stops there. Nothing says a `ruff` or `black` FAIL on its own file is its to fix before reporting.

Fixing it needs no implementation access. The lint lives in files under the scrivener's own write lane, `hooks/lanes.py:215-222`, and `ruff` and `black` read and rewrite only the path given. What `hooks/no-impl-reads.py` denies is unchanged; its count of the shell's invocations, `hooks/no-impl-reads.py:88`, is not.

Lint is dir-wide where the suite run is not. `scripts/blind.sh:170-171` lint `"$tests"`, the whole directory, while the runner at `scripts/blind.sh:169` takes `"$rel"`. So a scrivener's own run can FAIL on a file another block pinned.

## What the owner sees change

Seven readings.

- Scrivener hits `FAIL ruff` or `FAIL black` on the file it wrote. Runs `scripts/blind.sh format <same path>`, re-runs `test`, reports a clean gate. No re-request.
- Scrivener runs `format` on a path outside `<tests dir>/`, or on two paths, or with any second command: denied by `hooks/blind-bash.py`, same denial text as any other shape.
- Bailiff runs `format`: denied. Its one read command is unchanged.
- Scrivener's run FAILs on a file no brief of its names: `format` on that path is admitted by the hook and refused by the agent's own rule. The hook admits any path under the lane, so what holds here is `agents/scrivener.md`, not the tree.
- `ruff check --fix` leaves errors it cannot fix: `format` writes what it fixed and exits non-zero, listing the residue. Scrivener fixes the rest by `Edit` and re-runs `test`, and a residue it cannot fix is a finding it reports.
- No `ruff` and no `black` installed: `format` dies on the floor at `scripts/blind.sh:178`, `no gate for <path> is installed, so nothing ran`, rather than exiting 0 having done nothing.
- A lane file whose extension is not `.py`: the eslint branch, exactly as `cmd_test` reads today at `scripts/blind.sh:167-176`.

## What it costs

The blind shell goes from three commands to four, and the fourth is the first that writes. Every previous line of defense here was "the shell cannot write at all"; after this it is "the shell writes one tool's output into one path inside one lane, for one caller". That is a narrower guarantee, and `hooks/blind-bash.py`'s caller gate is the whole of what holds it.

`CLAUDE.md:35`, "The lane hooks stay on and unweakened", is the repo rule this runs at. A shape added to `ALLOWED` widens what `blind-bash.py` lets through, so this plan amends that hook's admitted set in the open rather than narrowing a matcher to land a change: no entry commented out, and `--self-test` gains a row for every shape added and every caller refused.

`ruff check --fix` can delete an unused import that was the tell of a wrong test. Safe fixes only, and the diff is the scrivener's to report, but the class of loss is real and is not fully closed by excluding `--unsafe-fixes`.

Tests for the new shapes land under `<tests dir>/`, which is closed to the main agent, `hooks/lanes.py:215-222`. They come through an approved spec block and the scrivener, like any other test in this repo.

`scripts/blind.sh` carries no `--self-test` and gains none here: its behavior is exercised through `hooks/blind-bash.py --self-test` and the suite, and adding a self-test arm to a `bwrap`-wrapped shell script is its own change.

Left out: narrowing `test`'s lint to the file argument, for the reason under Which files get touched, and any change to what `no-impl-reads.py` denies.
