## What is wrong

The red run is the one gate in the chain with no artifact and no lane. Every other gate has both. `docs/gauntlet/plans/<slug>.txt` is written by `gauntlet-prosecutor` and denied to every other hand at `.claude/hooks/plans-lane.py:47` and `:49`; `docs/gauntlet/specs/<slug>.txt` is the same shape one stage later; `docs/gauntlet/reviews` is one lane at `.claude/hooks/reviews-lane.py:78`, shared by the two reviewers named at `:72-74`, each of which also owns exactly one approved-artifact lane and no other's — `SECOND_WRITE` at `:82`. The verdict on the red run has neither. It exists as lines in a transcript.

Two defects follow, and they are different defects.

The first is that nobody can check a verdict after the fact. `scripts/pair.sh:99` saves the run output to `state/red/$slug.txt`, so the evidence is on disk, but nothing on disk says what was ruled on it. A `RED 1-4` in a transcript is a claim by whoever typed it, and `docs/approved-specs.md` is the repo's own statement that a gate whose evidence is a transcript is not a gate.

The second is that nothing constrains who issues it. The main agent has read the implementation. It is the one hand in the chain that must not rule on whether a test bit, and it is currently free to write the verdict, to paraphrase one, or to skip the round and report that it passed. `.claude/agents/gauntlet-juror.md` says the verdict is the juror's; a prompt is not what makes that true, which is the argument `.claude/hooks/no-impl-reads.py` is built on — the agent that must not peek is the same agent deciding whether it peeked.

Outside `.claude/worktrees/`, the only mention of `state/verdicts` anywhere in the tree is `.claude/agents/gauntlet-juror.md:63`, in the agent file written before this plan. No hook, no wiring, no writer, and no `Stop` hook beyond the two markdown gates.

## What the owner sees change

A red run produces a file. `docs/gauntlet/verdicts/<slug>.txt` holds one verdict per behavior line and nothing else, tracked, so it is there to read after the session that produced it is gone and on a machine that never ran it — the same reason `docs/gauntlet/plans/` is tracked.

Writing it is denied to every hand but `gauntlet-juror`, at the tool call, the way the three existing lanes deny theirs. A main agent that writes its own verdict gets the lane's denial and the message names the agent that may.

A turn that ends with `state/red/<slug>.txt` present and no matching verdicts file is blocked, and the block says which slug was never ruled on. Skipping the round stops being a thing that is noticed later and becomes a thing that does not land.

## What it costs

A fifth lane hook, and a fifth `--self-test` on the bar in `CLAUDE.md`, which lists seven gates and would list eight. Every consumer of this repo re-copies `.claude/` and re-runs the list; `CHANGELOG.md` carried that same breaking note for `0.1.0`.

A stale sentence in a file this plan does not touch. `.claude/hooks/no-impl-reads.py:29-31` explains the `docs/gauntlet/` denial as covering "three of the four kinds" of artifact that live there. A fifth directory lands and that arithmetic is wrong — comment only, no behavior, and the denial itself keeps working exactly as written.

One tracked file per red run, in a fourth artifact directory under `docs/gauntlet/`. That is the cost the owner took when they answered the escalated question: the verdict is checkable on a machine that never ran the suite, and the repo carries a file per run forever to get it.

The `Stop` gate keys on a file's existence, and six readings of that have to be settled in the first version rather than when each first bites.

**Abandoned run.** A slug the owner dropped, a worktree cut and discarded: its red file sits there and blocks every turn until a verdict exists or the red file goes. The block names the file to delete, and deleting it is denied to nobody.

**Re-run.** `scripts/pair.sh:100` writes `state/red/$slug.txt` with `>`, so a second `pair.sh red` overwrites the evidence in place while the first run's verdict file still exists and still satisfies the gate. The gate would pass on a verdict that ruled on output no longer on disk — the exact defect this plan opens with, reintroduced. So the gate compares the two rather than counting them, and it does the comparison itself: a verdict file whose `mtime` is older than the red file it answers fails the gate exactly as a missing verdict does, because the evidence has been rewritten since it was ruled on.

The comparison is the hook's, not the juror's, and that is the point of putting it there. `.claude/agents/gauntlet-juror.md:63` says the verdict file holds "one verdict per line and nothing else in the file" and `:3` says "and nothing else"; keeping the run's identity out of the file leaves both sentences standing. It also has to be the hook's: `:4` gives the juror `Read, Grep, Glob, Write` and `:69` says it holds no `Bash`, so it can neither stat nor hash the file it ruled on. An earlier draft of this plan had the verdict file record an `mtime` or hash, which was a redefinition of the artifact that no owner sentence authorized and that its writer could not have carried out.

`mtime` ordering is the whole of the test, so the one way to defeat it is to write a verdict and then restore an older red file over it. Nothing in the chain does that, and a hand that does is not one a `Stop` hook was going to stop.

**Empty file.** `:100` redirects before the suite runs and appends `|| true`, so a crashed or killed run leaves a zero-byte `state/red/$slug.txt`. That is not a run to rule on. An empty red file is not a verdict the gate should demand; it fails with its own message, naming the run that produced nothing.

**Many slugs.** The gate scans a `state/red/` directory rather than one path, so several unruled slugs block at once. It names every one of them, not the first.

**Which `state/red/`.** `scripts/pair.sh:99` writes the file relative to the cwd `pair.sh` ran in, and this repo has agents working inside `.claude/worktrees/<slug>-spec` and `-impl`, which `shell_shapes.py:397-400` treats as roots by construction. The `--stop` half resolves its root from its own path, `Path(__file__).resolve().parent.parent.parent`, which is how the repo's one existing `Stop` hook does it at `scripts/gates/check_md_trivia.py:63`. Neither the cwd nor `CLAUDE_PROJECT_DIR`: the cwd moves within a turn, and `CLAUDE_PROJECT_DIR` is the main checkout for one session and the worktree itself for another, so keying on either makes the gate's subject depend on how the session was launched.

Resolving from the script gives each checkout its own gate over its own `state/red/`. A session launched inside `.claude/worktrees/<slug>-spec` runs that tree's copy of the hook and is gated on that tree's directory; a session at the root that merely `cd`s into the worktree runs the root's copy and is gated on the root's. The gap this leaves is real and worth naming: a `pair.sh red` run from inside a worktree writes a red file the root's gate never sees. It is narrow — `scripts/pair.sh:98-99` is written to be run from the main checkout, and `cmd_red` at `:86` dies unless the worktree exists beneath it — and closing it properly is a `pair.sh` change, which the owner scoped out of this plan.

**No `state/red/` at all.** Every turn in a consumer project that copies `.claude/` per `README.md:50` and never runs `pair.sh` has no such directory. A missing directory is not an unruled run: the gate returns silently and blocks nothing. It fires on a red file that exists, never on the absence of one, which is also what keeps it quiet for `kind: excision` and `kind: repair`.

A tests-only change never reaches any of this. `README.md:44` says a `kind: excision` or `kind: repair` change has no red run, so `state/red/<slug>.txt` never appears for those two kinds and the gate stays silent. Nothing in `scripts/pair.sh` enforces that — `cmd_red` at `:82-102` has no `kind` guard, and only `cmd_merge` branches on kind, at `:113-118` — so the silence comes from the documented chain and not from the script. A `pair.sh red` run by hand on an excision slug would produce a red file and arm the gate against a change that owes no verdict.

Deliberately left out: the parse in `scripts/pair.sh red`, and items 3 and 4 of the backlog. The owner scoped this to "its hooks".
