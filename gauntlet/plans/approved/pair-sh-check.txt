## What is wrong

Gate and land are one verb. `scripts/pair/cli.py:234` runs `converge.gate` and `scripts/pair/cli.py:260` runs `converge.land` inside one `_converge_and_land`, under one lock, on one invocation. Owner cannot see a pair's gate reading without also authorizing the land that follows it in the same process.

A red gate leaves nothing a later verb reads: `scripts/pair/converge.py:36` `report_red` writes to stderr, and the one file it leaves, `scripts/pair/converge.py:53`, is the same `<gauntlet dir>/merge/<slug>.txt` a green merge overwrites at `scripts/pair/blocks.py:160`. One path per slug, so a second run erases the first reading.

Nothing records which tips a gate reading was taken over.

## What the owner sees change

Five readings. The first four on one pair whose gate is red:

- `pair.sh merge <slug>` prints `UNCHECKED <slug>`, exit 1. Nothing lands. No gate runs.
- `pair.sh check <slug>` prints `CHECK <gauntlet dir>/merge/<slug>.1.txt FAIL`, exit 1. Target branch untouched.
- a code commit on `impl/<slug>`, then `pair.sh check <slug>` prints `CHECK <gauntlet dir>/merge/<slug>.2.txt PASS`, exit 0. `.1.txt` still on disk.
- `pair.sh merge <slug>` then prints its `TEST CHECK` brief naming `.2.txt`, lands, cleans up. Target branch moves here and nowhere before it.

The fifth is the target branch moving between a green `check` and the `merge`: `merge` rebases, the recorded target sha is no longer the tip, and it prints `UNCHECKED <slug>`, exit 1. Rerun `check` over the rebased trees.

A `motion: strike`, `motion: amend` or `motion: rehome` pair reads the same. `check` runs its gate and writes the numbered artifact whatever the structure line; `merge` reads that artifact, then prints the `strike-diff.py` verdict lines and lands as it does today.
