## What is wrong

An approved plan is frozen the moment it lands. `docs/plans.md:10` gives the artifact as written by `gauntlet-prosecutor` "on `READY`, and only then".

The owner's approval is what opens the next stage, at `docs/plans.md:72`. Nothing in that document says what happens to the plan file afterwards.

The value that goes stale is a measured one. A plan is written before implementation, so its readings — a call-site count under check (c), a boundary reading under check (f), anything carrying `ASSUMED` under check (b) — are taken against the tree as it stood at drafting. Implementation is where the real number arrives, and `.claude/agents/gauntlet-prosecutor.md:59` admits `ASSUMED` only for a reason that is "metered action, live experiment, or owner decision", which is to say for exactly the readings that implementation later settles.

Today that leaves two moves, and both are wrong. Leaving the plan as it stands puts a number on disk that the tree contradicts, in the one artifact a later stage reads instead of inheriting from a conversation. Redrafting it costs a full gate run and a second approval word over text the owner already read: `README.md:45` says "One word opens one artifact as it stands", so a redraft is a new artifact and every check runs again.

The scope rule that would make the cheap move legal already exists and stops short of this case. `.claude/agents/gauntlet-prosecutor.md:43` says the checks "run on the changed sentences and the citations they carry, and on nothing else", with every untouched check printing `carried`. That rule governs rounds before `READY` only — `:39` frames it as re-review inside a drafting run, and `:47` makes `READY` the terminal act that writes the plan file.

The backlog line the owner opened an earlier session with names both halves together, at `docs/gauntlet/plans/juror-verdicts-lane.txt:100`: "plan rechecks on changed lines only, with an amendment carrying a measured value from the impl tree".

## What the owner sees change

A new round kind, the amendment round, runs after approval and during implementation.

The main agent returns to a `gauntlet-prosecutor` with three things: the slug, each amended line named by its first words with its new text, and the measured value with the command that produced it and that command's output. Nothing else — the plan body is on disk and the reviewer reads it there.

The main agent is what takes the measurement, and the command is what makes that safe. `.claude/agents/gauntlet-prosecutor.md:29` holds that the main agent is not a reliable narrator, so the amendment carries a command the reviewer re-runs rather than a number the reviewer trusts. A measured value with no command that reproduces it is not an amendment.

The reviewer may be a fresh one, and this is what makes the round cheap rather than a re-run under another name. `.claude/agents/gauntlet-prosecutor.md:47` has the approved file carry "`--- reviewer ---` divider and your whole output verbatim beneath it", and `:25` already admits "approved plans under `docs/gauntlet/plans/`" to its reading list. So a reviewer that holds none of the original round can still read every previous verdict, from the plan file, without touching the reviews directory — which `:45` denies it "by `Read`, `Grep` or shell".

Checks run on the amended lines and their citations, and on nothing else. Every other check prints `carried` with the verdict from the most recent `--- reviewer ---` block, quoted as that block has it. The reversal sentence at `:43` still applies: a new finding on unchanged text stays legal and costs one scoped round.

On `READY` the reviewer rewrites `docs/gauntlet/plans/<slug>.txt`: the amended plan body, then every reviewer block in order, oldest first, each under its own `--- reviewer ---` divider. A slug amended twice carries three blocks, and a reviewer reading the file for carried verdicts takes the last one. The owner reading the file sees what the amendment changed and what carried across it.

An amendment whose measured value changes no plan line is not a round. The reviewer is not spawned, the file is not rewritten, and the main agent records the reading in its own report. A round exists where a line changes, and nowhere else.

The amended plan then waits for the owner, on the same terms as the first one. `docs/approved-specs.md:50` states it for the sibling artifact — "A rewritten file is a new artifact, so the owner's approval of the one before it does not carry" — and `README.md:45` states it for this one. A rewritten plan takes its own approval word before implementation continues on it.

A verdict other than `READY` writes nothing, and the approved file on disk is the one that stands.

An amendment round does not count toward whatever round leash the consuming project sets on the plan gate. This repository defines no such leash: the eight-round stop is named at `.claude/agents/gauntlet-prosecutor.md:88` and nowhere else, as the exemption an `ESCALATE: QUESTION` round takes. An amendment arrives from the implementation tree rather than from a plan that cannot settle.

## What it costs

The work is prose in four files and no code.

Three rules in force are touched, and one of them is overturned. `docs/approved-specs.md:48` says of the spec gate that "An approved file is amended the same way it was created: the revised block goes back to a `gauntlet-arbiter`, and the reviewer that returns `READY` rewrites the file", and `docs/plans.md:13` binds the plan lane to that document by name. This plan overturns "amended the same way it was created" for plans and for plans only: a plan amendment is a scoped round, a spec amendment stays a full re-review. `docs/approved-specs.md` keeps its rule and takes no sentence, and the departure is stated in the new `docs/plans.md` section, where the plan gate's own rule lives.

`docs/approved-specs.md:50` is the second, and it is not overturned but adopted: the rewritten plan takes its own approval word, on the same reasoning as the rewritten spec file.

`docs/approved-specs.md:38` is the third. The approved spec shape carries one `--- reviewer ---` block, and all three files now in `docs/gauntlet/plans/` carry exactly one. An amended plan carries more, oldest first. The spec shape is unchanged and the two artifacts stop being the same shape, which is the price of the scoped round: the carried verdicts have to be readable from the plan file, because the reviewer cannot read `docs/gauntlet/reviews/` at all.

It buys a round that can go wrong in a way the current chain cannot: an amendment is a write over the artifact the owner approved. The mitigation is the older reviewer blocks staying in the file rather than being replaced, so the text the first approval covered is still readable beneath the amendment.

No test covers it, and none covers its neighbours either. `test_hook_wire.py:385` tests that only the plan reviewer may write an approved plan, which is the hook behavior this change deliberately leaves alone; no test in the repository reads `docs/plans.md` or any file under `.claude/agents/`. The change lands as a `docs:` commit and takes no stage 2, on the owner's line 4: a spec block here would have to invent a shape check over prose, and the precedent it costs is that the gauntlet's own rule prose changes outside the gauntlet.

Deliberately left out, on the owner's line 5: the pre-`READY` recheck stays at changed sentences, at `.claude/agents/gauntlet-prosecutor.md:43`, and the changed-sentences rule is not written into `docs/plans.md` as its own rule. The new section states the amendment round's scope only.
