> delivered: this plan changes `.claude/hooks/no-impl-reads.py` alone and leaves `scripts/pair.sh` to its own chain.

## What is wrong

`.claude/hooks/no-impl-reads.py` denies a blind agent every path under `docs/gauntlet/` except `docs/gauntlet/specs/`, because the plans, the drafts and the reviewer rounds quote implementation citations: `.claude/hooks/no-impl-reads.py:208` is the denial, and the docstring states the reason at `:30-31` — "of the four kinds quote implementation citations".

The denial is a test on one path. `readable()` at `:169` resolves a single target, tests it against `GAUNTLET_SPECS`, then against `GAUNTLET_BASE` at `:208`, then against the allow list at `:212`. A path that is an *ancestor* of the denied subtree passes every one of those tests, because `docs/` is an allow-list entry at `:86`.

Both reading surfaces score paths with that one test. The Bash stage does it at `:368` — "if any(not readable(w, root, here, allow) for w in _candidates(words))". `_verdict()` does it for the search tools at `:382` — "return None if readable(target, root, cwd, allow) else _WHY" — where a `Grep` or `Glob` carrying a path is readable-tested and nothing asks what the search will walk into. Neither surface asks the containment question, and the one containment rule that exists, `_unrooted_sweep()` at `:259`, fires only when every candidate is `.` or `..` — "return all(w.rstrip(os.sep) in UNROOTED for w in _candidates(words))" at `:263` — so a root of `docs/` takes a command out of that test rather than into it.

Measured against HEAD (`9cbabc3`), feeding each command to the hook on stdin as a `Bash` tool call:

```
grep -rn cite docs/       -> ALLOW
find docs/ -name "*.txt"  -> ALLOW
git grep -n impl -- docs/ -> ALLOW
rg impl docs              -> deny
ls -R docs                -> deny
grep -rn x .              -> deny
```

The three allows each print the content of the plans, the drafts and the reviewer rounds under `docs/gauntlet/` — the files `Read` is denied at `:208`. `Grep` with `path` set to `docs` or `docs/` is allowed by the same reasoning at `:382`, and returns the same lines with no shell involved. The blindness guarantee is path-shaped, and a sweep is not a path.

The two shell denials are accidental rather than load-bearing: `docs` without a trailing slash carries no `/` and no extension, so `_candidates()` at `:225` does not see it as a path at all, the candidate list comes back empty, and `all()` over an empty list makes `_unrooted_sweep()` true. The same command spelled `rg impl docs/` is allowed. A guarantee that turns on a trailing slash is not a guarantee.

Reach today. `no-impl-reads.py` is wired on four agents — `.claude/agents/gauntlet-juror.md:11`, `.claude/agents/gauntlet-scrivener.md:11`, `.claude/agents/gauntlet-arbiter.md:11`, `.claude/agents/gauntlet-bailiff.md:11`. On the shell road the `gauntlet-scrivener` and the `gauntlet-bailiff` also run `blind-bash.py` (`.claude/agents/gauntlet-scrivener.md:23`, `.claude/agents/gauntlet-bailiff.md:35`), whose one-command grammar refuses a `grep` outright, so shell exposure is the `gauntlet-arbiter` alone. The `Grep` road has no such cover: `blind-bash.py` is wired on the `Bash` matcher only, so `Grep(path="docs")` reaches the plans from all four agents, the `gauntlet-juror` included, which holds no Bash tool at all. The `Grep` hole is the wider of the two.

## What the owner sees change

A blind agent's recursive read that would print content out of a directory containing a denied subtree comes back denied, naming the subtree it would have walked into. That is one rule on two surfaces: `grep -rn x docs/`, `find docs -name '*.txt'` and `git grep -n x -- docs/` are refused, and so is `Grep(path="docs")`. A search rooted at `docs/gauntlet/specs/`, at the test directory, or at a named file still passes, and the refusal says to root deeper.

`Glob` is not touched. It returns filenames and no content, the ground `.claude/hooks/reviews-lane.py:77` already states — "`Glob` returns names only and is not one" of the content tools — and `.claude/agents/gauntlet-arbiter.md:56` mandates one every round that carries verdicts, whose only working spelling at HEAD is rooted at the ancestor: "Glob `docs/gauntlet/reviews/<slug>.[0-9]*.txt` first". Containment on `Glob` would deny an agent the round number it is required to compute.

Nothing else moves. A non-recursive read is judged exactly as it is today, a runner invocation is untouched, and an agent that never sweeps sees no change.

## Which files get touched, and roughly how

`.claude/hooks/no-impl-reads.py`. One containment helper beside `_unrooted_sweep()` at `.claude/hooks/no-impl-reads.py:259`, which answers: does this root resolve to a directory that has the denied subtree inside it? Denied subtrees are the ones `readable()` already knows — `GAUNTLET_BASE` at `:88` minus `GAUNTLET_SPECS` at `:90` — and the helper anchors a root the way `readable()` does at `:192-196` — "base = sh.root_by_name(resolved) or root" — so a worktree root is relative to its own tree. With no repo base the helper denies, the direction `readable()` takes at `:197-198` and the direction the docstring states at `:18-21`.

Three call sites. `_verdict()` at `:378-382` calls it for `Grep`, which is recursive by construction and prints lines; `Glob` keeps the judgement it has today, for the reason above. `_bash_verdict()` at `:329` calls it for a command `_reads_recursively()` (`:238`) says walks a tree. The git branch at `:359-367` calls it inside the `_git_prints_content()` arm at `:363`, rather than by head word or for every git command: `_reads_recursively()` keys on the head word, which for every git command is `git`, so `git grep` and `git show <rev>:<dir>` are sweeps the head word cannot tell apart, while `git log --oneline -- docs/` prints metadata and is allowed at HEAD. `git ls-files docs/gauntlet/plans/` stays allowed too, returning names and no lines, which is the line this plan draws for `Glob`. The arm that already separates the two is the one to hang containment on, and it needs no subcommand list of its own. `.claude/agents/gauntlet-bailiff.md:57` — "`git show <spec-commit>:docs/gauntlet/specs/<slug>.txt`" — prints content and survives, since its root resolves inside `docs/gauntlet/specs/`.

A root is an operand, whether or not it carries a trailing slash. `_candidates()` at `.claude/hooks/no-impl-reads.py:225` keys on a `/` or an extension, which is why `find docs` has no candidate at all today; for a recursive command the roots are taken by operand position instead, lexically, with no filesystem probe: for the grep family and `rg` the first non-flag word is the pattern and every later one is a root, unless `-e`, `-f`, `--regexp` or `--file` has already supplied the pattern, in which case no operand is the pattern and every non-flag word is a root; for `find`, `tree` and `ls` every non-flag word is a root. Without that second clause `grep -rn -e cite docs/` has `docs/` promoted to pattern, carries no root, and goes through containment untested — as do `grep -rn -f patterns.txt docs/`, `grep -rne cite docs/` and `rg -e cite docs/`. `grep -rn docs tests/` therefore has one root, `tests/`, and passes — the pattern is not a root because of where it sits, not because of what it names.

A value-taking option is skipped with its value (`-e`, `-f`, `--regexp`, `--file`, `-m`, `--include`, `--exclude`), and the two spellings are not the same skip: an attached value consumes no further word — `--include=*.txt` and `-m3` are one word and one skip — and only a separated one consumes the word after it. Read the other way, `grep -rn --include=*.txt cite docs/` eats `cite`, `docs/` becomes the pattern, no root is left and the sweep goes through, which is an under-denial at exactly the edge this rule exists for. Where a word cannot be placed the helper treats it as a root and denies. That is the fail-closed direction the docstring states at `:18-21`, and it over-denies rather than under-denies.

A new refusal string beside `_UNROOTED` at `:117`, naming the subtree walked into. `_UNROOTED` itself at `:118` stops advising `docs/` as a root — it advises `docs/gauntlet/specs/` and the test directory — since under this change `docs/` is exactly the root that is refused, and advice that names a denied root is worse than no advice.

The module docstring bullet list at `:66-69`, which today names only the unrooted sweep, and the allowlist paragraph at `:17-38`.

Self-test cases in `self_test()` (`:418-562`), beside the existing recursive cases at `:475-484` and the `docs/gauntlet` denial cases at `:515-536`. The `--self-test` is one of the ten gates, so the new rule prints its own `PASS` line.

`CHANGELOG.md`, one entry under `[Unreleased]` / `Fixed`, in the same commit as the change.

The pinned cases land in this repository's test lane, written by the `gauntlet-scrivener` from the approved block. Not mine to write, and no file is named here.

## What this overturns

Three rules in force say `grep -rn secret docs/` is allowed, and this change denies it. They are overturned deliberately, and each takes the delta the chain requires.

- `docs/gauntlet/specs/shell-shape-classification.txt:59`, line 5 of that approved block — "`grep -rn secret docs/` -> SILENT". The line is re-specified in the block this plan leads to, so the approved text that carries `SILENT` is replaced rather than contradicted in silence.
- `tests/test_hook_wire.py:340` in `test_unrooted_recursive_search_is_denied`, which asserts "grep -rn secret docs/": SILENT. It changes through the approved block and the `gauntlet-scrivener`, never by hand.
- `.claude/hooks/no-impl-reads.py:481`, case 5 of the hook's own `--self-test` — `allowed(bash("grep -rn secret docs/"))`.

The rule those three state — a rooted search is not a sweep — is not wrong; it is under-specified. A root inside the allowlist that contains a denied subtree was never considered when they were written.

## Caller-side delta

None in this repository. No agent definition changes, no hook is re-wired, `blind-reads.json` gains no key — the denied subtree is the hook's own constant, not repo data, and `.claude/hooks/no-impl-reads.py:37` is explicit that no `blind-reads.json` entry may re-open the gauntlet base.

A consumer copying `.claude/` gets a stricter hook with no action on their side.

## What it costs

The `gauntlet-arbiter` loses `grep -rn x docs/`, and all four wired agents lose `Grep(path="docs")`. Each roots at `docs/gauntlet/specs/`, at the test directory, or at a named docs file instead. That is the intended loss.

A `find docs` that only lists names is refused with the rest of the shell road, where `Glob` is not. The split is the tool, not the intent: a shell name-lister carries its own options for printing content — `find docs -exec cat {} +` — and the `Glob` tool has none. On the shell road the hook keeps the direction it already takes with git, where `_git_prints_content()` at `:286` rules on the same question, and its docstring at `:289-290` says "an unrecognized subcommand is treated as content".

The accepted leak is slug names through `Glob`: a reviewer that globs `docs/gauntlet/reviews/` learns which slugs have rounds. Names are not citations, and the same slugs are readable in `docs/gauntlet/specs/` already.

A lexical operand grammar is what costs here. It is guessing at a shell, and a spelling it cannot place is denied rather than allowed, so an arbiter meets a refusal on an exotic invocation and roots deeper.

`docs/` stays on `DEFAULT_ALLOW` at `:86`. Narrowing it instead would deny the non-recursive reads of `docs/testing.md` and the rest that a blind agent is meant to have.

Three in-force rules are overturned, listed above, each costing a re-specified line and a delta to the writer.

Left out: the `scripts/pair.sh` blob-SHA defect, which the owner's brief puts on its own chain — "each takes its own chain".
