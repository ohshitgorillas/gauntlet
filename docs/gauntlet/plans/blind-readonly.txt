## What is wrong

`scripts/blind.sh test tests/<file>` is denied by `.claude/hooks/tests-lane.py`, and the denial is a misclassification rather than the lane rule working.

The classifier is a closed allowlist of head words. `shell_shapes.py:360` ends `segment_writes` with `return head not in READ_ONLY`, and `READ_ONLY` at `:36-45` holds bare basenames of printing utilities — `"basename", "cat", "cksum", "column", "comm", "cut", "diff",` at `:38` through `"yq",` at `:43`. `os.path.basename("scripts/blind.sh")` is `blind.sh`, which is on no list, so the stage scores as a write.

The one escape above that line is the runner table. `:351` reads `if is_runner(words):` and returns `False` for a suite run, and `is_runner` at `:262` is described at `:265` as `A closed table of whole invocations.` Its members are `pytest`, `python -m`, `node --test`, `npm|pnpm|yarn test`, `npx <runner>`, `cargo test` and `go test` — every one a bare basename, none a repo-local script. `scripts/blind.sh` is not in it, so the escape does not fire.

With the stage scored a write, `lane_write_in` at `:396` matches the lane token in the argument and `tests-lane.py:94` returns its denial: `return _BASH if sh.lane_write_in(command, BASH_TESTS) else None`. The message the agent reads is `_BASH` at `tests-lane.py:67-71`, which begins `A shell write naming a tests/ path is denied: `.

What the denied command runs is a branch of gates over the lane, not one run of a named file. `blind.sh:97` branches on `*.py`. The Python side is `blind.sh:98-100`: `run_gate pytest "$ROOT/.venv/bin/pytest" "$rel" -q -p no:cacheprovider`, `run_gate ruff "$ROOT/.venv/bin/ruff" check tests` and `run_gate black "$ROOT/.venv/bin/black" --check tests`, the last two over the whole lane rather than the named file. The other side is `:101-103`: `run_gate node node --import ./tests/js/support/vendor-resolve.js --test "$rel"` and `run_gate eslint npx eslint "$rel"`.

Each gate runs under the sandbox at `blind.sh:57-67`, which binds `/` read-only — but `cmd_test` invokes it at `:89` as `sandbox --bind "$tree/tests" "$tree/tests"`, and `:56` says `Extra arguments bind a path back writable`, so the lane is the one writable path inside the run. `CHANGELOG.md:13` states the same shape: `with the filesystem read-only apart from the agent's own lane`.

So the sandbox is not what keeps the lane unwritten, and the plan does not claim it is. What keeps it unwritten is the form of the gates: `ruff check` without `--fix`, `black --check` and `eslint` without `--fix` report and do not rewrite, and pytest is invoked with `-q -p no:cacheprovider` and `PYTHONDONTWRITEBYTECODE=1` at `blind.sh:90`, so it leaves neither a cache directory nor a `.pyc` behind. Two residues are real and both are stated rather than closed here: a test already committed in the lane can write inside the lane when it runs, because the lane is bound writable at `blind.sh:89`; and the `npx eslint` at `:103` can fetch a package, because `blind.sh:57-67` unshares pid but not the network. Neither is reachable by typing — the command carries no content of its own and no argument that is not a path — but the second means `test` on a non-`.py` argument is not offline, and the plan says so rather than calling the whole subcommand read-only.

The denial reaches the two agents the script was written for. `.claude/agents/gauntlet-scrivener.md:15` wires `tests-lane.py` over a matcher that carries `Bash`, so the blind writer's only way to run the tests it just wrote comes back denied. ## The entry is declared, not compiled in

`docs/approved-specs.md:82` states a standing rule for the kit: `Nothing in hooks/ depends on anything outside hooks/. There is no allowlist to import, no budget to configure, no repo layout assumed.` `shell_shapes.py:9-10` gives the reason: `It is deliberately standalone. These hooks travel as a unit into other repos,`. A table entry naming `scripts/blind.sh`, with a path shape anchored at `tests/`, compiled into `shell_shapes.py`, breaks both — the module would carry one repository's layout into every repository it is copied to.

So the entry is not compiled in. `shell_shapes.py` gains a loader for a sibling config and a table of *declared* runner invocations read from it, each declaration being an entry path, its fixed argument words, and the path prefix its one remaining argument must sit under. This repository declares `scripts/blind.sh`, `test`, and the test directory; a repository that copies `.claude/` and declares nothing gets the table it has today.

The loader is not new. `no-impl-reads.py:130-131` already reads `blind-reads.json` beside it — `path = os.path.join(os.path.dirname(os.path.abspath(__file__)), "blind-reads.json")` — for exactly this kind of per-repo widening, and that file does not exist in this checkout today. The loader moves into `shell_shapes.py` and `no-impl-reads.py` calls it there, so one module reads the config and two use it.

The project config the owner names — `the project will have a config file soon` — does not exist at 50ff923: the repository root carries `CHANGELOG.md`, `CLAUDE.md`, `LICENSE`, `README.md` and the `.claude/`, `docs/`, `scripts/`, `state/` and `tests/` directories, and no configuration file of any name. So the declaration lands in `hooks/blind-reads.json` and migrates when that file arrives. If it is added before implementation starts, the declaration goes there instead and this plan takes an amendment rather than a redraft.

`docs/approved-specs.md:82` is overturned in one clause and is rewritten with this change: `There is no allowlist to import` stops being true of `shell_shapes.py` once it reads a sibling config, and it was already inexact for `no-impl-reads.py:130-131`. The other two clauses survive, and survive better than under a compiled-in entry: there is still no budget to configure, and with the layout declared rather than assumed, `no repo layout assumed` becomes true of `shell_shapes.py` in a way a hard-coded `tests/` would have made false.

## The seam, and what it widens

The change goes in the runner table at `shell_shapes.py:262`, not in `READ_ONLY` at `:36-45`. `READ_ONLY` is the wrong seam twice over: its members are bare basenames, so a `blind.sh` entry would admit any file of that name on any host, and its question is whether a head only ever prints, which is not what this script is — it runs gates. The runner table asks the question that fits: is this whole invocation a run of the project's suite.

The key is the whole invocation, arity included: `words[0]` normalized and ending in the declared entry path, the declared argument words after it, exactly one argument after those, and that argument matching the declared path shape — `TESTPATH` at `blind-bash.py:64`, which moves into `shell_shapes.py` as the shape a declaration's prefix is expanded into. `blind-bash.py` imports it from there, so the one regular expression has one definition.

The regular expression is not the whole key, and the plan says so rather than claiming the two sites cannot differ. `TESTPATH` at `blind-bash.py:64` ends `[A-Za-z0-9._/-]*`, which admits `.` and `/` and therefore admits `..`: `tests/a/../../docs/gauntlet/plans/y.txt` matches it. What refuses that today is not the shape but `blind-bash.py:90`, `if ".." in command:` inside `_allowed_command` at `:88-92`, and that check does not move with the constant. So the classifier takes its own traversal refusal: the declared entry's one argument is normalized with `os.path.normpath` and must still sit under the declared prefix after normalization, or the invocation is not a run. The two sites then refuse the same set for a different reason — `blind-bash.py:90` on the raw command text, the classifier on the normalized path — and that is the reading, rather than one shared definition.

The loader constrains a declaration for the same reason. A prefix is normalized when it is read, and a declaration whose prefix resolves to or under any lane directory — `docs/gauntlet/plans`, `docs/gauntlet/specs`, `docs/gauntlet/verdicts`, `docs/gauntlet/reviews` — is dropped. Without that, a declaration alone would turn off the lane hook that guards it, and the rules below would rest on the content of a file rather than on the classifier.

One standing rule covers this surface directly and is not overturned. `CLAUDE.md:31` reads `**The lane hooks stay on and unweakened.** They are the product, so disabling one to land a change ships the defect rather than hiding it. No matcher narrowed, no entry commented out, no `--self-test` left failing.` Every hook stays wired at the matcher it has today, no entry is removed, and the change adds four `--self-test` cases and a tenth gate rather than leaving one failing. What moves is what the classifier calls a write, for one declared invocation, under the two constraints above; a hook that denies a run of the suite is the bug in the hook that line's last sentence describes, fixed in the hook.

Six files read the classification this change touches, five of them lane hooks, and each is named here with the rule it holds.

`tests-lane.py:94` is the denial this change exists to lift, and the rule at `tests-lane.py:67-71` is the one discussed above. Overturned, deliberately, for the one declared shape.

`plans-lane.py:73`, `specs-lane.py:69` and `verdicts-lane.py:95` each read `sh.lane_write_in(...)` and reach `is_runner` through `segment_writes` at `shell_shapes.py:351`. Their rules — one writer per lane, the plan gate's stated at `docs/plans.md:13` as `hooks/plans-lane.py denies every other hand at the tool call, so the presence of docs/gauntlet/plans/<slug>.txt is the evidence that those words passed the plan gate` — are **not** overturned, and the declared path prefix is what holds them. `scripts/blind.sh test docs/gauntlet/plans/x.txt` fails that prefix, so it is not a runner, so it stays a write, so each of those three denies it exactly as today. Without that constraint all three would stop denying it, which is why the declaration carries a prefix rather than an entry alone.

The prefix holds those rules only with the normalization above, and the reach if it did not is total rather than partial. `segment_writes` at `shell_shapes.py:351` returns `False` for a runner and `lane_write_in` at `:396` skips a stage that does not write before it ever tests the lane pattern, so anything the declared shape admits is invisible to all five lane hooks at once. `scripts/blind.sh test tests/a/../../docs/gauntlet/plans/y.txt` matches the raw shape, so without the classifier's own `os.path.normpath` check `plans-lane.py:73` would return `None` and the one-writer rule at `docs/plans.md:13` would be overturned in silence. With it the argument normalizes outside the declared prefix, the invocation is not a run, and the denial stands.

Who may write the declaration is the second half of that answer, and it is not guarded. No lane hook pattern covers `.claude/hooks/`, so the main agent may write `.claude/hooks/blind-reads.json` at any time; `plans-lane.py`, `specs-lane.py`, `tests-lane.py` and `verdicts-lane.py` each guard their own `docs/` lane and nothing else. This is why the two constraints above sit in the loader and the classifier rather than in the file: a declaration is data that widens, and every bound on what it can widen is code a declaration cannot edit. A declaration naming a lane directory is dropped, and one naming `tests/` widens exactly the lane `tests-lane.py` already lets a runner through.

`no-impl-reads.py:351` reads `if sh.is_runner(words) or (head in runners and not inline): continue`, so a run's arguments are not walked for implementation paths. After this change a blind agent's `scripts/blind.sh test <path>` skips that walk where today it is walked. The skip is bounded by the same declaration: an argument outside the declared prefix is not a runner and is walked as before. `blind-bash.py:71` bounds it a second time for those two agents, admitting only `test <TESTPATH>`. This is why the frontmatter wiring lands in the same change: the skip and the anchored grammar are one rule.

`reviews-lane.py:142` reads `if sh.command_writes(command, restore_ok=False)`, so a reviewer may run `scripts/blind.sh test <test path>` afterwards. A reviewer may already run `pytest`, so this adds a spelling and no capability.

The runner enumeration is prose in three places, and all three move: `reviews-lane.py:44-52`, which enumerates the read-only runner forms as `pytest`, `python -m pytest`, `node --test`, `npm test`, `npx vitest`; `reviews-lane.py:104-105`, the same list inside `_REVIEWER_BASH`, which is the text a denied reviewer actually reads; and `shell_shapes.py:23`, the module docstring's account of the table. Each gains the declared form. None of the three may stay stale: a reviewer reads the second one at the moment it is denied, and the third is where the table's rule is stated.

`no-impl-reads.py:44-51` says the common runners need no `runners` entry because `shell_shapes.is_runner` recognizes them by whole invocation. Its text changes only where it describes where the config is read, since the loader moves; the rule it states is not overturned.

The edges of the key read as follows.

- An absolute path ending `scripts/blind.sh`, a copy at `.claude/worktrees/<slug>-spec/scripts/blind.sh`, or `../scripts/blind.sh`: each a run. `blind-bash.py:71` matches from the start of the command text, so the blind agents are denied these spellings and keep the repo-relative one.
- `bash scripts/blind.sh test <path>`: not a run. `words[0]` is the interpreter at `shell_shapes.py:273`, the suffix does not match, and the lane denial stands — which is also `blind-bash.py:71`'s reading, since a command word in front of the entry is not admitted.
- `scripts/blind.sh test` with no path, or with two: not a run, by arity. The script itself refuses both at `blind.sh:70`.
- A second argument outside the declared prefix — `docs/gauntlet/plans/x.txt`, `.claude/hooks/shell_shapes.py`, `/etc/passwd`: not a run. Each stays a write and each lane hook rules on it as it does today.
- A second argument under the prefix that is not a `.py` file — `tests/js/x.test.js`: a run, and it takes the `blind.sh:101-103` branch, so the gates are `node --test` and `npx eslint` and the run is not offline. The classification is the same; what runs is not.
- A second argument naming the test directory itself, or a directory under it: a run where the declared shape admits it, which it does for a name with no extension. The script then fails it at `blind.sh:79`, whose `[ -f "$tree/$rel" ]` test refuses anything that is not a regular file. The classifier is permissive here and the script is not.
- A second argument under the prefix naming a file that does not exist: a run, refused the same way at `blind.sh:79`.
- A second argument that starts under the prefix and walks out of it — `tests/a/../../docs/gauntlet/plans/y.txt`, `tests/../.claude/hooks/shell_shapes.py`: not a run. The raw shape admits both, since `TESTPATH` at `blind-bash.py:64` ends `[A-Za-z0-9._/-]*`; the classifier's own normalization refuses them, and for the two blind agents `blind-bash.py:90` refuses them a second time on the raw command text. Each stays a write and each lane hook rules on it as it does today.
- `scripts/blind.sh status <slug>` and `show <commit> <slug>`: not runs, and not unreached either. They fall to `READ_ONLY`, score as writes, and name no lane — so `tests-lane.py`, `plans-lane.py`, `specs-lane.py` and `verdicts-lane.py` let them pass both today and after, while `reviews-lane.py:142` judges a reviewer's command with no lane path in it at all and denies both today and after. That denial is unchanged by this plan: a reviewer is not a blind agent and has no use for either subcommand.

## What it costs

One spec block and one blind test-writing round, for a change that is a moved loader, a moved constant, a declared-entry table, one new config file, four self-test cases, three prose sites, one gate, two frontmatter entries and two roster cells. Larger than the hard-coded seam it replaces, and the standing rule at `docs/approved-specs.md:82` is what it buys.

The config is read at hook time, once per tool call, by every lane hook rather than by `no-impl-reads.py` alone. A malformed `blind-reads.json` currently costs one agent its widening; afterwards it costs every lane its declared runners. The loader's existing failure mode — `except (OSError, ValueError):` at `no-impl-reads.py:135-136`, returning an empty config — is the safe direction for a lane, since an empty config denies rather than admits, and it stays as it is.

The classifier now encodes which argument shapes a declared entry accepts, which is knowledge the script itself already holds at `blind.sh:79`. Two sites judge the same argument and they can disagree: the classifier admits a directory or a missing file that the script refuses. The disagreement is safe in this direction — the script is the stricter of the two — and it is stated rather than fixed, because making the classifier resolve paths on disk would put filesystem access in a pure shape-reading module.

Left out deliberately: the two residues named under "What is wrong" — a committed test writing inside the writable lane bind, and `npx eslint` reaching the network on the non-`.py` branch — are stated and not closed. Closing either changes `scripts/blind.sh`, which is a different surface from the classifier this block is about.
