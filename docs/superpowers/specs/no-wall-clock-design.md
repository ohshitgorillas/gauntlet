## Why

The quality gates spec bars clock reads and sleeps from test files, and the owner's task bars every wall clock and every slow test, with no exception. The tree has four kinds of clock in `tests/`, real time in `gates/` that no test can turn, and the same few helpers copied from file to file to carry them.

**Clock reads and sleeps in test code.** `time.monotonic` deadlines with `time.sleep` polls: `tests/test_core_checker_group.py:103`, `:108`, `:111`, `:116`; `tests/test_core_checker_signals.py:110`, `:118`, `:128`, `:130`, `:180`, `:187`, `:201`; `tests/test_core_checker_run_all_signals.py:129`, `:137`, `:142`, `:144`, `:147`; `tests/test_heavy_checker.py:67`, `:72`, `:106`, `:108`.

**Timed waits.** A positive timeout on a blocking wait, which the spec's rule does not reach: `tests/support/scripted.py:50` (`Event.wait(WAIT)`) and `:53` (`Event().wait(step.hold)`, a sleep under another name); `tests/test_heavy.py:204`, `:219`, `:225`, `:344`, `:345`; `tests/test_heavy_checker.py:54`, `:105`; `tests/test_heavy_lock.py:65`; `tests/test_heavy_dash_dash.py:63`; `tests/test_heavy_leading_dash.py:53`; `tests/test_core_checker_signals.py:136`; `tests/test_core_checker_run_all_signals.py:193`; `tests/test_support_capture.py:209`, `:293`, `:547`; and the capture helper's own bound, `tests/support/capture.py:29`, `:179`, `:357`.

**Sleeps in child code.** Strings run as child processes or as seeded test modules: `tests/test_core_checker_group.py:46`, `:55`, `:70`; `tests/test_core_checker_signals.py:65`, `:79`; `tests/test_core_checker_run_all_signals.py:50`, `:57`–`:59`, `:77`; `tests/test_heavy_checker.py:42`; `tests/test_check_pytest_parallel.py:35`–`:39`, `:47`–`:50`; `tests/test_check_pytest_cpus.py:42`; `tests/test_check_pytest_processes.py:35`.

### `tests/support/scripted.py`: an in-process Runner that paces `run_all` by events (decisions 9, 10)

Its job is to make concurrent calls overlap, order and end by events alone, with no timeout and no hold, and to leave no thread blocked when a test fails. It replaces `WAIT` and `hold` (`tests/support/scripted.py:17`, `:26`, `:50`, `:53`) and every `HOLD` its callers pass (`tests/test_core_checker_run_all.py:27`, `tests/test_core_runner_budget.py:30`). The pytest gate's cap tests reach it through `run_gate(..., process=..., next_done=...)` (`gates/core/runner.py:212`), and the budget tests through `Run.process` (`gates/core/runner.py:116`) and `Run.next_done`, which `check_with` hands to `run_all` (`:170`). So the seeded rendezvous modules (`tests/test_check_pytest_cpus.py:30`, `tests/test_check_pytest_processes.py:25`) and their 10-second give-up go too.

A test hands a `Scripted`'s `next_done` to `run_all` beside the `Scripted` itself, as `run_all`'s `next_done` keyword, as `Run.next_done`, or as `run_gate`'s `next_done` keyword, and `run_all` makes every wait on its workers through it (decisions 9, 10). Each call is held from its start until `run_all` waits through `next_done` with that call under way and every other call it has started under way or done. So when the code runs the cap's number at once, they certainly run together, and `peak` is the cap. Code that starts more than the cap shows a `peak` above it. Code that takes a Command before a slot frees but starts no more than the cap, or never waits through `next_done`, leaves `next_done` or a call blocked, and the test fails at pytest-timeout's bound. `next_done` hears that a future is done through the future's done callback, so what it blocks on is an event too.

Every block in the test's thread while `run_all` runs a `Scripted`'s calls is a wait on its workers, so it is inside `next_done`, the cleanup's wait included (decision 9). Any exception raised there, pytest-timeout's included, closes the `Scripted` before it goes on: every call still blocked raises `Released`, the workers end, the cleanup's waits return, and the executor's join finds no worker left. That rests on two facts, which the spikes of steps 34 and 35 prove, one wait each, before step 36 builds on them (decision 11): pytest-timeout's default signal method raises in the main thread, and a lock wait with no timeout gives way to a signal handler on POSIX from Python 3.2, below the `>=3.12` floor (`pyproject.toml:8`). In the test's thread a `Scripted` blocks only in a `threading.Condition` wait and in `first_done`'s `concurrent.futures.wait`, the two waits those spikes prove.

A test that hands a `Scripted` as its process without its `next_done` holds every call for good: `run_all` then waits through `first_done`, nothing releases a held call, and the cleanup's wait outlasts pytest-timeout's one signal, so `make check` hangs. G6's Scripted rule fails every test file that could make that slip, so the pairing is checked mechanically (decision 12). The rule is built with G6 (decision 13); until G6 lands, `test-reviewer` holds the pairing. In a test file that imports `tests.support.scripted`, every Runner handed to `run_all`, `Run`, `run_gate` or `dataclasses.replace` is a plain name `p` with `next_done=p.next_done` in the same call, so every Runner such a file hands those calls has a `next_done`. A `FakeRunner` (`tests/support/fake.py:16`) has none, so such a file hands it to none of them, where `tests/test_core_runner_budget.py:120` hands one to `Run` through `_checked` (`:73`); and a `Scripted` built inside the call, as at `tests/test_core_checker_run_all.py:61`, is bound to a name first.

```python
class Released(Exception):  # a call or a next_done still blocked when its Scripted closed
    name: str                 # the call's name, or "next_done"
    def __init__(self, name: str) -> None: ...

def last_argument(command: Command) -> str: ...  # the default key: the Command's last argv word

@dataclass(frozen=True)
class Step:
    reply: Completed | BaseException
    after: tuple[str, ...] = ()   # names whose calls have finished before this call returns

class Scripted:  # a Runner whose next_done a test hands run_all beside it, safe across threads; every wait blocks on an event and has no timeout
    called: list[str]
    finished: list[str]
    peak: int                     # the most calls seen running at once
    def __init__(self, steps: Mapping[str, Step], *, key: Callable[[Command], str] = last_argument) -> None: ...
    def __call__(self, command: Command) -> Completed: ...  # held until next_done releases it, then blocks on `after`, then replies; once closed, raises Released
    def next_done(self, running: Collection[Future[Completed]]) -> set[Future[Completed]]: ...  # blocks until each future in running has its call under way or is done, releases every held call, then returns first_done(running); any exception inside it, pytest-timeout's included, closes first and goes on; once closed, first_done(running) alone
    def close(self) -> None: ...  # every call and next_done still blocked raises Released, and every later call raises it at once
```

### `tests/support/lifeline.py`: child processes held, met and ended by pipes

Its job is every wait a test makes on a real process: ready, held, met and ended, each one an event on a pipe or FIFO. It replaces the 3 `_drain` copies, the 3 `_kill_leftovers` copies, the 3 kill-at-the-bound waits, the 4 file polls and the 3 sleeping grandchildren listed under **Why**. It also replaces `_alive` (`tests/test_heavy_checker.py:57`), `_settle` (`tests/test_heavy.py:216`), `_hold` (`tests/test_heavy.py:231`), whose shape it generalises, and the sleeping child code at `tests/test_core_checker_group.py:46`, `:58`, `tests/test_core_checker_signals.py:68`, `tests/test_core_checker_run_all_signals.py:53` and `tests/test_heavy_checker.py:38`.

```python
class Lifeline:  # a pipe whose write end only the test holds; a child reading its read end to EOF lives until release
    read_fd: int
    def __init__(self) -> None: ...
    def release(self) -> None: ...                 # close the write end; a second call does nothing
    def __enter__(self) -> Self: ...
    def __exit__(self, *exc: object) -> None: ...  # release, then close the read end

class Witness:  # a FIFO the test reads; every process that opens it to write is a holder
    path: Path
    def __init__(self, path: Path) -> None: ...    # makes the FIFO and opens its read end without blocking
    def ended(self) -> bytes: ...                  # called after every holder's ready line: blocks, with no deadline, until every holder has closed it; returns what they wrote
    def __enter__(self) -> Self: ...
    def __exit__(self, *exc: object) -> None: ...

def ready(fd: int) -> bytes: ...  # block until a child writes one line on fd and return it; b"" when every writer closed first

class Beacon:  # a pipe a child writes one ready line on; the test reads it once the child has started
    write_fd: int  # handed to the child through Command.pass_fds and its argv
    def __init__(self) -> None: ...
    def seen(self) -> bytes: ...                   # close the test's write end, then ready() on the read end: the line, or b"" when every child holding the write end closed it first
    def __enter__(self) -> Self: ...
    def __exit__(self, *exc: object) -> None: ...  # close each end still open

class Pids:  # the pids children note in a file, killed by pid at teardown
    path: Path
    def __init__(self, path: Path) -> None: ...
    def noted(self) -> list[int]: ...
    def __enter__(self) -> Self: ...
    def __exit__(self, *exc: object) -> None: ...  # SIGKILL each noted pid; ProcessLookupError passed over

HOLD: str     # child code: write a ready line to fd 1, then read fd int(sys.argv[1]) to EOF and exit 0
WITNESS: str  # child code: open the FIFO at sys.argv[1] to write, write a mark, write a ready line, then HOLD on fd int(sys.argv[2])
MEET: str     # child code: open the FIFO at sys.argv[1] for reading or writing as sys.argv[2] says; returns once the other side has opened it
```

`MEET` is a two-process rendezvous: a FIFO's open blocks until both ends are open. A seeded test module that must end after another one opens such a FIFO and reads it to its end, which comes when the other module's process has exited. That replaces the timed waits at `tests/test_check_pytest_parallel.py:30` and `:43`.

A `Beacon` is the event a group test waits on before a virtual cap passes (decision 14). The checker writes its line on the `Beacon`, which reaches it through `Command.pass_fds` (`gates/core/checker.py:45`), once its child has written its mark into the `Witness`, and the test hands `beacon.seen` to its `VirtualClock` as `after`. `seen` runs inside `run`, once the checker has started, so closing the test's write end there leaves the checker's copy alone: the line comes when the group is whole, and end of file comes at once when the checker dies before writing, so neither path waits on time.

### `tests/support/clock.py`: a virtual clock (decisions 6, 14, 16)

Its job is to be the one clock a test hands to code that waits on time. Its time moves only as the test sets it, and it never hands a `Ready` a positive number, so no wait on it reads or waits on real time. It replaces the time-cap tests' wall-clock cap (`tests/test_core_checker_group.py:28`, `:139`, `:151`) and the 60-second cap at `tests/test_core_runner.py:915`.

```python
class VirtualClock:  # a Clock whose time moves only as the test sets it
    now: float  # virtual seconds passed, from 0
    def __init__(self, *, passes: float | None = None, after: Callable[[], object] | None = None) -> None: ...  # passes: the seconds that pass in a wait whose event has not come at its poll, None: time stands still; after: blocks, with no timeout, until the event the test proves against has come, None: nothing to wait for
    def wait(self, ready: Ready, seconds: float | None) -> bool: ...  # ready(0) first, True when it comes; when False and passes is None, ready(None); when False and passes reaches seconds, after(), then ready(0) again, True when it comes, otherwise now += seconds and False; otherwise now += passes, then ready(None)
```

A still `VirtualClock()` never lets a cap pass, so a wait on it ends on its event alone. `VirtualClock(passes=p)` with `p` at or past the cap lets the cap pass at once, in virtual time, when the event has not come at the clock's first poll. `after` holds that moment back until an event of the test's own has come (decision 14). `run` makes its one wait as soon as the checker has started (`gates/core/checker.py:99`), so the clock's first poll can come before the checker has started anything of its own, and a test that proves what the cap's kill reaches hands an `after` that blocks until the checker's whole group is up. `after` runs in the test's thread, inside `run`, once the checker has started, so it blocks on a pipe a live child holds, and that pipe's end of file comes at once when the child dies first.

`now` moves only in a wait whose event had not come at the clock's first poll, by `passes` or by the cap, so its value after a wait is as certain as that poll's outcome (decision 16). A test asserts `now` only where an event fixes that outcome: a child a `Lifeline` holds is certainly alive at the poll, and a still `VirtualClock()` never moves `now` at all. `main`'s command-line test (`tests/test_core_runner.py:915`) runs a child that exits on its own, so it hands `run` a still `VirtualClock()` and asserts nothing of `now`.

## Homes

A test waits only on an event: a pipe or FIFO opening, a line arriving, end of file arriving, a thread event being set. It blocks on that event with no timeout of its own. The one bound on a test that hangs is pytest-timeout's 30 seconds, so a hang costs time only when a test fails. It runs under its default signal method, which raises in the test's main thread and goes on to the next test (decision 11), so every wait a test makes is either on a pipe or FIFO in its own thread that a `Lifeline`, `Witness` or `Beacon` ends, or inside a `Scripted` that closes on any exception in a wait. Time a test needs to pass passes on a `VirtualClock`, never on the wall (decision 6). The one test that waits on real time is `SystemClock`'s own, kept on its own in `tests/test_core_clock_real_time.py`, its cap a few hundredths of a second (decision 16). A test whose pass path needs something not to happen proves it through an event the code gives, or through a fake handed in as an argument, never by waiting for a while to see. A child process lives only as long as a pipe whose write end the test holds, so it dies when the test lets it go or when the test's process ends. Concurrent calls in process run on a `Scripted`, handed to `run_all` with its own `next_done` beside it (decision 10), which holds each call until `run_all` waits through that `next_done` with it under way, so the cap's number certainly run together, and which closes on any exception in a wait, so no blocked thread outlives a failing test (decision 9).

Real time enters `gates/` at one place, `SystemClock` in `gates/core/clock.py`. Every wait in `gates/` that can end on time as well as on an event goes through a `Clock` handed in, `SYSTEM` by default, and keeps its own wait on the event as the `Ready` it hands that clock (decision 6). The checker's exit wait (`gates/core/checker.py:226`, `:242`) is such a `Ready`. A test that hands `run` a positive cap hands it a `VirtualClock` too, and no test runs a positive cap on `SYSTEM` but the one real-time test, which hands `SystemClock` its cap directly, with no `run` around it (decision 16). A still `VirtualClock()` never lets the cap pass and never moves `now`, so the wait ends on the child's exit, as `main`'s command-line test needs (`tests/test_core_runner.py:915`), and that test asserts nothing of `now` (decision 16). A test that proves the cap itself hands `run` a positive cap and `VirtualClock(passes=...)` at or past it, against a child a `Lifeline` holds: the child is certainly alive at the clock's first poll, so the cap passes at once in virtual time and `run` reports `timed_out`, with no real time spent. A test that proves what the cap's kill reaches also hands the clock `after=beacon.seen`, so the cap passes only once the checker has written on its `Beacon` that its child holds the `Witness` (decision 14). `run_all`'s cleanup waits on its workers' end with no time in it at all (decision 7).

G6's clock rule reaches timed waits (decision 1). A test file fails on any positive number given as the timeout of a blocking wait: `wait`, `join`, `result`, `communicate`, `subprocess.run`, `call`, `check_call`, `check_output` and `select`. A cap handed to `Command` or to `python_module`, and a number handed as the `seconds` keyword of a `wait` call, which is a `Clock`'s cap, stay data (decisions 16, 18); the same number handed to a `wait` by position is a timed wait. Steps 1 and 5 write that into the rule, and G6 builds it when its turn comes. Child code in strings is out of any gate's reach, so `test-reviewer` holds it.

G6 carries a Scripted rule beside its clock rule (decision 12). A test file that imports `tests.support.scripted` or any name from it fails on a call to `run_all`, `Run`, `run_gate` or `dataclasses.replace`, under any name the file imports it by, that does not hand its Runner as a plain name `p`, to `run_all` as its first argument and to the others as the `process` keyword, with `next_done=p.next_done` in the same call; a `replace` that passes no `process` is outside it. Such a file also fails when it names any of the four anywhere but in its import and as a call's function, as `functools.partial(run_all, ...)` does, or when it imports a name from another test file. A `conftest.py`, and a Python file under `tests/support/` other than `tests/support/scripted.py`, fails that imports `tests.support.scripted`; a Python file under `tests/support/` fails that calls `run_all`, `Run` or `run_gate`. So a `Scripted` reaches those calls only in a test module that imports it, and there it comes with its own `next_done`. The rule reads files under `tests/support/` as the seeded-literal rule does. Step 1 writes it into the test-shape gates, and G6 builds it with its other test-shape rules, on the layout G6's own design gives them, which no spec yet gives beyond one line; no step here builds it (decision 13). Until G6 lands, `test-reviewer` holds the pairing, and a test that slips it hangs `make check` until `test-reviewer` sees it.
