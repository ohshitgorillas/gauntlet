# Quality gates for building Gauntlet

Status: approved 2026-10-18.

## Intent

Gauntlet is built by agents before it can build itself. Gating is extremely strict and trust in agent-written code is low. The outcome wanted is coherent, cohesive, correct, easily testable code: no shortcuts, no patches, no workarounds. A small bug that shows a whole system is wrong leads to the system being rebuilt, not the symptom patched.

These gates go in before any product code. M1 starts under the full set.

## Principles

1. **A gate must be impossible to satisfy without the code getting better.** A gate an agent can pass by reshaping code, rather than improving it, is not included.
2. **No count caps.** Nothing triggers on a number of arguments, returns, branches, statements, lines, nesting levels, files per directory, or a complexity score. Whether a unit does too much is a question for the reviewer.
3. **No coverage threshold.** Test quality is judged by mutation testing. Coverage is measured only to find lines mutation testing cannot see.
4. **No suppressions.** No inline suppression comment, no per-file ignore, no exemption table, no baseline, no ratchet. A finding is fixed in the code.

## Gates

All gates run from one entry point, `make check`, which pre-commit invokes.

- Every gate applies to every Python file in the tree: `gauntlet/`, `tests/`, gate scripts, and any hook or tool script.
- A Python file is a file whose name ends in `.py` or `.pyi`, or an extensionless file whose first line is a shebang that names python; a `.pyw` file is not one.
- A gate's verdict on a Python file is the same whatever other files the tree holds.
- Every gate is a script under `gates/` that `make check` runs; a gate whose checker is an external tool runs that tool over the tree's Python files with the settings in `pyproject.toml`, which holds those settings and nothing else does, and returns the checker's findings.
- A gate exits 0 with no finding, 1 with one or more findings, and 2 when its checker could not finish; it prints each finding on its own line and prints its count line on every run.
  - The count line of a run whose checker finished reads `<gate>: N finding(s) in M Python file(s)`, where `<gate>` is the name of the gate script without its extension and `finding(s)` and `file(s)` are printed as written whatever N and M are, and it is the last line the run prints. A file given more than once, under one spelling or under two that are the same path once made absolute, as `a.py` and `./a.py`, is one file: checked once, counted once in M and named as first given.
  - A run whose checker could not finish prints the same count line as the last line it prints, after what the checker reported.
  - A checker finished only when its exit status is the one the checker documents for the report it gave, as mypy's 1 with one or more errors and 0 with none. A checker that exits with any other status, that a signal or a time cap ends, or whose output holds no report the gate can read did not finish: the gate prints the checker's whole output, stdout and stderr, as what the checker reported, then, for a checker its time cap ended, one line of its own naming the cap, and exits 2. A status the checker documents as a stop whose report still stands, as mypy's 2 on a blocking error, is not a finish either, and the gate prints the report it read. Only a gate's own bullet rules otherwise, as the mutation gate's wall-clock cap does.
  - Besides what the checker reported, the findings the gate read and the count line, a run prints nothing: no line of the gate's own giving the checker's exit status, the file the checker stopped on, or why the gate could not read its report. A gate's own lines are a closed set: the line saying nothing was checked, the error below that names a `pythonVersion` key, the pytest gate's seed line, and one error naming what kept the gate from running its checker: temp space it cannot make, copy or delete, a `pyproject.toml` it cannot read, a checker that cannot start, or a checker that ran past its time cap.
- A Python file the checker cannot read or cannot parse is a file the checker did not finish: the gate prints what the checker reported for that file and exits 2, whatever it found in the other files.
  - A gate that parses a Python file parses it with the grammar of the pinned Python, which is pyright's `pythonVersion` in `pyproject.toml`, and a `pyproject.toml` that sets no `pythonVersion`, or one that is not a `major.minor` version, is one the checker could not finish: the gate prints an error that names the key, then its count line, and exits 2, and never falls back to the grammar of the interpreter it runs under.
  - A parse that cannot run to its end, as when it runs out of depth or memory, is one the gate could not make, and its file is a file the checker did not finish, by the rule above.
  - A warning raised while a gate parses a Python file is an error for that parse, so its file is a file the checker did not finish: the gate prints the warning as the checker's report and exits 2.
- A gate given no Python file it checks makes an empty run: it prints one line saying that nothing was checked, then the count line `<gate>: 0 finding(s) in 0 Python file(s)`, and exits 1.

A test file is a Python file the pytest strictness bullet under Tests defines as one, and that definition is the one definition of a test file for every gate. A test is a function whose name starts with `test`, at module level in a test file or as a method of a module-level class whose name starts with `Test`. Own code is the packages `gauntlet` and `gates`. A gate whose checker reads files other than Python files, such as `pyproject.toml`, `uv.lock` or the `Makefile`, still takes the tree's Python files, counts them as M in its count line, and makes an empty run when given none. A gate changes no file it checks and applies no fix.

### Types

- mypy with `strict = true`, plus `warn_unreachable = true`, `disallow_any_explicit = true`, `disallow_any_expr = true`, and every optional error code in `enable_error_code`. `python_version = "3.12"`, `requires-python = ">=3.12"`, ruff `target-version = "py312"`.
  - Each run of the mypy gate warms one temp mypy cache on no repo file; every per-file mypy run starts from its own copy of that warm cache. The warm cache and every copy live under the run's scratch root, which is the system temp directory as Python's `tempfile` gives it unless the caller hands the run another, and never in the tree. A warm or a copy that fails makes the run one the checker did not finish: the gate prints the error, then its count line, exits 2, and never falls back to uncached per-file runs. The warm cache and every copy are deleted on every exit path, a run that did not finish included, and a deletion that fails makes the run one the checker did not finish. mypy's cache directory is passed on its command line and changes no verdict. A test judges where the warm cache and its copies live only by the scratch root it hands the run and by the tree, never by `TMPDIR` or by mypy's cache file names or layout.
  - The mypy gate prints mypy's stderr. On a stop (mypy's exit 2) a non-empty stderr is printed as Unfinished after the records, so an `INTERNAL ERROR` crash shows; on a finish a non-empty stderr is printed as Remarks, which count no finding.
- pyright in `strict` mode.
- `typing.cast` is banned (ruff `TID251`). The ban is on the function, not its spelling: it covers `typing.cast` under every name it is imported by, `typing_extensions.cast` included, and the banned-api table lists each such name.

### Lint and format

- ruff `select = ["ALL"]`, `preview` off. Every stable rule of the locked ruff runs except the `ignore` list below, and every other ruff option keeps its default save `target-version` and the banned-api table of Types; no pydocstyle `convention` is set, since one turns `D` rules off, and an option set otherwise is a finding. So `D104` holds for every `__init__.py`, an empty one included: every package carries a module docstring. A finding is one ruff diagnostic and names the file, line, column, rule code and ruff's message.
- `ignore` holds only:
  - `C901`, `E501`, `W505`, `PLR0911`, `PLR0912`, `PLR0913`, `PLR0915`, `PLR0917`;
  - `D203`, `D213`, `COM812`, `ISC001`;
  - `S603`.

  Each ignore carries a one-line reason comment in `pyproject.toml`. The reason is a `#` comment on the entry's own line, after the entry, and says why the rule is off; an entry with no comment there, or an empty one, is a finding.
- `per-file-ignores`: `tests/**` gets `S101` only. `tests/**` matches every file under `tests/` at any depth and nothing outside it.
- ruff format in check mode. A finding is one file the formatter would change, named by its path.

### Suppression gate

A gate script fails on any of the items below. The comment markers of the first two items are found by tokenizing and match only inside a comment token, never inside a string. A marker matches anywhere in the comment, ignoring case and the whitespace around the colon and between its words, so `#mypy:`, `# FMT: OFF`, `# type:ignore` and `x = 1  # note; fmt:skip` are each a finding. A marker needs no word boundary on either side, so `# notmypy: x` and `# fmt: offset` are each a finding too. A comment that carries more than one marker is one finding that names every marker it carries, as `# pyright: ignore`, which contains `# pyright:`, does.

- a `noqa`, `type: ignore`, `pyright: ignore`, `pragma: no cover` or `pragma: no mutate` comment;
- a `# mypy:`, `# pyright:`, `# fmt: off` or `# fmt: skip` comment;
- a `@typing.no_type_check` decorator. The ban is on the function, not its spelling: it covers `typing.no_type_check` and `typing.no_type_check_decorator`, `typing_extensions` included, and any reference to either is a finding wherever it appears: imported, bound to another name, used as a decorator or called, so the import line and the assignment line are each a finding.
  - A use of a name is a finding when any binding of that name, in the scope Python's scoping rules resolve the use to, is either function, with no path or reachability condition: a binding counts whether it is conditional, followed in that scope by another binding of the name, deleted on some or every path, or behind code that never runs, and a binding made through `global` or `nonlocal`, in a class body, a comprehension or by an assignment expression counts whether or not its body ever runs.
  - A `match` capture pattern or a `for` target that takes either function as its value is a binding that is the function. The value is followed when the `match` subject is the function itself or when the subject, or the iterable of a `for` statement or comprehension, is a list, tuple or set display written in place, into the targets its items reach, and the same holds for the targets of an assignment whose value is such a display written in place; a container reached through another name is not followed, and the line that puts the function into it is the finding.
  - A starred target is bound to a list, never to the function, so a use of it is no finding. A set display has no item order, so each target its items reach takes every one of them; where its items are themselves displays unpacked into nested targets, each nested target takes every item in turn.
  - The name an `as` pattern binds is a capture, and binds the function when what its pattern matched is the function. The line of a `case` whose capture pattern binds either function is a finding, as an assignment line is, and is the line its `case` keyword sits on, however many lines its pattern spans. A set never matches a sequence pattern, so the captures of a sequence pattern over a set subject bind nothing.
  - Finding it takes a parse with the grammar of the pinned Python, 3.12, so a file that grammar cannot parse, syntax added in 3.13 or later included, is a file the gate did not finish, by the rule of the Gates intro. Only the parse is covered: a file the gate reads and parses is a file the gate finishes, with exit 0 or 1, and an error in the gate's own resolution of names on such a file is a defect of the gate, never a file it did not finish;
- a `per-file-ignores` entry other than `tests/** = ["S101"]`;
- an `ignore` entry not on the list above, or `preview` on;
- any mypy `[[tool.mypy.overrides]]` section, or a pyright rule downgraded from strict;
- any path excluded from a checker: ruff `exclude`/`extend-exclude`, mypy `exclude` or `follow_imports` other than `normal`, pyright `exclude`/`ignore`, coverage `omit`;
- any ignore list in another tool's config: mutmut `do_not_mutate`/`do_not_mutate_patterns`, import-linter `ignore_imports`, a filepawl exempt table or allowance baseline, a deptry ignore, a vulture whitelist, a pytest `filterwarnings` entry other than `"error"`, coverage `exclude_lines`/`exclude_also`;
- a pytest-timeout `timeout` mark in any form, a `conftest.py` that disables or unregisters a pytest plugin, or a pytest `addopts` entry that disables one.

### Tests

- **Mutation testing blocks.** mutmut runs on every commit, with no cache, over the functions the commit changes in every given Python file that is not a test file, and mutates no other function; a `conftest.py` is never mutated, whether or not it is a test file.
  - A changed function is one with a changed or added line in `git diff HEAD` over the given files, and every function of a new file is a changed function.
  - Any surviving mutant fails the gate. There is no score threshold. The fix is a test that kills the mutant, or deleting code no behavior depends on. An equivalent mutant means the code is rewritten.
  - In the count line M is every given Python file that is not a test file, one that yields no mutant included, and no test file is counted; a given file with no changed function yields no mutant, is not a file mutmut skips, and still counts in M. A `.pyi` file is given and counted in M, holds no statement to mutate and so yields no mutant, and is never a file the checker did not finish. An extensionless file whose shebang names python is mutated as a `.py` file is. Any other file mutmut skips or cannot process is a file the checker did not finish: the gate prints mutmut's report for it and exits 2, and never drops it silently.
  - The suite is every given test file, chosen by the pytest bullet's rule below, and each mutant runs against the tests of the suite that mutmut's own coverage record shows reaching the mutated function; a mutant no test reaches is a finding by the next bullet. Every pytest run the gate makes takes the settings and rules of the pytest bullet.
  - A mutant is killed only when a test fails on it; one that survives, that no test reaches, that outlasts mutmut's own time limit, under which a test runs past pytest-timeout's 30 seconds, or that mutmut marks suspicious, skipped, segfaulted or caught by type checking is a finding, named as mutmut names it and carrying the change mutmut made. mutmut's own time limit is mutmut's default: a `pyproject.toml` key that changes it is a finding, as each narrowing or widening key below is, and the run uses the default.
  - The given files and their changed functions always win over `[tool.mutmut]`: a key that narrows the files mutated or the tests run below what this bullet chooses, as `paths_to_mutate`, `tests_dir` or `also_copy` can, or that widens the scope beyond the changed functions of the given files, is a finding that names the key.
  - A finding is one line: the file's path as given, the mutant's name as mutmut gives it, its status, then mutmut's whole diff with every line break in it replaced by a space. Findings print in order of path as given, then of mutmut's name.
  - The run uses at most floor(C / 2) workers, C being the CPU count the pytest bullet defines, and runs mutmut under `nice -n 19` and `ionice -c3`; a parallelism `pyproject.toml` sets above that cap is a finding that names the key, and the run uses the cap. A cap of 0 cannot start a run, and the gate exits 2.
  - Each run has a hard wall-clock cap of 600 seconds; a `pyproject.toml` key that raises it is a finding that names the key, and the run keeps 600 seconds. Hitting the wall-clock cap ends the run: every mutant not checked by then is a finding whose status is unchecked at the cap, and a run whose only unchecked mutants are these exits 1.
  - A run given no Python file that is not a test file is an empty run, by the rule of the Gates intro. A run given such files that yield no mutant at all is a finished run with no finding, and exits 0.
  - A run that leaves any mutant unchecked other than at the wall-clock cap, mutmut's interrupted and not checked mutants among them, whose suite does not pass on the unmutated tree, whose suite collects no test, or that is given files to mutate and no test file, is a run the checker did not finish. Such a run prints the checker's error, with the failing test ids when the suite failed on the unmutated tree, then every finding it found, then a count line, and exits 2 whatever it found.
  - mutmut works in a copy outside the tree, and the tree is byte for byte as it was after the run. A `mutants/` already in the tree is neither read nor deleted, and its Python files are files of the tree like any other, in scope for every gate. No result an earlier run left changes the verdict.
- **Seams:** tests use real git and filesystem. Podman and the Claude API never run in tests; seams take their process runner as a parameter. No test file imports `anthropic` or `claude_agent_sdk`, or any module under either, by any name. A test asserts the command a seam builds through a fake runner it hands the seam, and no test hands a command whose program is `podman` to anything that starts a process: `subprocess`, `os.system`, an `os.exec*`, `os.spawn*` or `os.posix_spawn*` function, or `asyncio.create_subprocess_exec` or `asyncio.create_subprocess_shell`.
- **No copy:** errors are typed exceptions carrying data; tests assert the type and the values they seeded. We don't pin wording that originates in the program. Wording that originates within the program's source code is not a valid pin. The gate for this is the last test-shape bullet below.
- **Unseen-line backstop.** A gate fails on any line, in a given Python file that is not a test file, that no test executes and on which mutmut generated no mutant, and lists each one.
  - It is a gate script of its own with its own count line: it generates its own mutant list and its own coverage and never reads the mutation gate's output. It writes nothing in the tree, and reads no `.coverage` or `mutants/` already there.
  - A line here is one coverage counts as a statement, and it is executed when any part of the test run, collection included, runs it and coverage records it; a line run only in a child process coverage does not trace is a finding. The test run is the given suite under the pytest settings.
  - The files are every given Python file that is not a test file, each whole whatever the commit changed; M counts each of them, a file with no statement included. Every given file is measured whatever `[tool.coverage]` says: a key that narrows measurement, as `source`, `include`, `run.omit` or a `data_file` in the tree can, is a finding that names the key. A `.pyi` file and an extensionless python-shebang file are handled as the mutation bullet handles them, a `.pyi` yielding no unseen line.
  - A mutant is on only the lines its change alters, so a statement's line carries a mutant only when a change touches the line coverage reports for that statement. Only a mutant mutmut ran exempts its line: one mutmut lists as skipped, or never checks, exempts none.
  - A finding is one line, `<path as given>:<line>`, and findings print sorted by path as given, then by line.
  - A failing test, a collection error, no test collected, coverage failing, mutmut failing to generate its mutants, a parse failure and a given file coverage cannot measure each make a run the checker did not finish: the gate prints the checker's error, then a count line, and exits 2.
  - The cap of mutation testing on parallelism binds the backstop's coverage run and mutant generation too, as there.
  - The gate exits 1 on any unseen line in any given file; a milestone that asks for the backstop to list nothing asks it of the tree, never of the gate's verdict.
- **pytest strictness:** `--strict-markers`, `--strict-config`, `filterwarnings = ["error"]`, `xfail_strict = true`, random test order (pytest-randomly), and a per-test timeout of 30 seconds (pytest-timeout).
  - The gate runs pytest under these settings over the test files among the Python files it is given: a file whose path as given has a `tests` directory component and whose name pytest collects by default, `test_*.py` or `*_test.py`, and any `conftest.py` beside one, so `tmp/tests/test_x.py` is one. Other given files are neither run nor counted, and a run given no such file is an empty run, by the rule of the Gates intro.
  - pytest takes its settings from the repository's `pyproject.toml` only; an ini file or `pyproject.toml` beside the test files is never read, whatever it sets.
  - The gate reads pytest's JUnit XML report and never parses pytest's console output; over a test file pytest finished it passes none of that output on, and over one pytest did not finish it prints pytest's whole console output as pytest's own error. A failing test is one finding: a test whose call, setup or teardown fails, an `xfail` test that passes, a test that raises a warning and a test that runs past the timeout each fail. A finding is one line: the test's id, which is the test file's path as the gate was given it followed by `::Class::test` as pytest names them, then a colon, a space and the failure's `message` attribute from the report, every line break in it replaced by a space. In the count line N is the number of failing tests and M the number of test files run.
  - Anything that stops pytest before or during collection is a run the checker did not finish, exit 2, with pytest's own error printed and the count line still printed: a collection error, an unknown marker under `--strict-markers`, a warning raised at collection, an unknown config key under `--strict-config`, a usage error, an internal pytest error, or no test collected from the test files given.
  - A failed test case in the JUnit report whose `classname` names a module other than the test module that pytest process was run over is never a finding: it makes a run the checker did not finish, exit 2, with pytest's own output printed and the count line still printed.
  - pytest-randomly and pytest-timeout are active on every run: the gate passes pytest no option that disables a plugin and hands it an environment without `PYTEST_ADDOPTS` and `PYTEST_PLUGINS`.
  - Each run takes a fresh random seed; before any finding the gate prints one line of its own, `<gate>: seed N`, with the seed pytest-randomly used.
  - Each test module, a test file that is not a `conftest.py`, runs in a pytest process of its own, so its verdict never depends on which other test modules are given; a `conftest.py` gets no process and is loaded by the modules beside it. The gate runs these processes in parallel, as many at once as there are test modules up to floor(C / 2) and never fewer than one, where C counts the CPUs the gate's process may run on, read in the gate's own process and never from a command: the CPUs its affinity allows where the host keeps an affinity, and the host's CPU count elsewhere, as on macOS; a host whose CPU count the gate cannot read is a run the checker did not finish, exit 2. Its output never depends on the order the processes end: each test module's lines, its findings or pytest's error in their place, print together and never interleave with another's, the modules in the order they were given, after the seed line and before the count line.
  - Each run of the pytest gate makes one temp directory of its own under the run's scratch root, before its seed line. The scratch root is the `scratch_root` argument of the gate's `main`, used as given and never checked against the tree; with none, it is the system temp directory as Python's `tempfile` gives it. Each test module's pytest process takes a path of its own inside the run's temp directory as pytest's `--basetemp`, which no other process shares and which pytest itself makes, so a `--basetemp` pytest cannot make or use is a run pytest did not finish over that module, with pytest's own output printed. The module's JUnit XML report lives inside the run's temp directory too. `--basetemp` is passed on pytest's command line and changes no verdict, so the rule that `pyproject.toml` alone holds pytest's settings stands.
  - The run's temp directory and all it holds are deleted on every exit path: every return and every exception, `KeyboardInterrupt` included, a run that did not finish among them. After a run the scratch root holds exactly what it held before, every other entry in it untouched. A run temp directory the gate cannot make, a missing scratch root included, prints one error line naming the path and the OS error, then the count line with N 0 and M the test files given, and exits 2. A deletion that fails, any entry left behind included, is temp space the gate cannot delete and is never passed over: after the seed line and every module's lines, the gate prints one error line naming the path and the OS error, then the count line with N the findings it read, and exits 2, whatever the modules found. A test may see its own process's temp directory through pytest's public `tmp_path` and `tmp_path_factory` API, and judges placement only by the scratch root it hands the run and by the tree, never by `TMPDIR` or by pytest's temp file names or layout. A run handed no scratch root leaves the tree byte-identical; where its temp space lives is not tested.
- **Test-shape gates**, from filepawl's suite gates and hqptuner2's test checks, applied to every test file:
  - no `unittest.mock`, `patch`, `monkeypatch` or `setattr` on code under test: a test file fails that imports `unittest.mock` or `mock` or any name from either, or names the `monkeypatch` or `mocker` fixture; so does a call to `patch` or to a chain ending `patch`, `patch.object`, `patch.dict` or `patch.multiple`, a call to any attribute named `setattr`, `delattr`, `setitem` or `delitem`, a builtin `setattr` or `delattr` on an imported name, an assignment, augmented assignment or `del` whose target is an attribute of an imported name, a `Mock`-family call with `spec` or `spec_set`, and any `create_autospec`, whatever each replaces; a collaborator's stand-in is a fake handed to the code as an argument;
  - no access to private names of the code under test: a private name begins with `_` and is not a dunder, and `_asdict`, `_replace`, `_fields`, `_field_defaults` and `_make` are public; a test file fails that reads or writes `x._name` where the test file does not itself define `_name` and `x` is not `self` or `cls`, that names such a name by string to `getattr`, `setattr`, `delattr`, `hasattr` or `patch.object`, or that imports own code through a module path with a private segment or imports a private name from it;
  - one claim per test: a test's claims are its `assert` statements at any depth of blocks, outside nested functions, lambdas and classes; `pytest.raises` and `pytest.warns` are not claims, an `==` between two tuple displays of equal length is one claim, and an `assert x is not None` or `assert isinstance(x, T)` whose `x` a later statement reads, followed by a later claim, is a narrowing guard and not a claim; a test with more than one claim fails;
  - no test that asserts only absence, or only existence or type: an absent value is `None`, `False`, `0`, `0.0`, `""`, `b""`, an empty list or dict display, a tuple display of absent values, the empty one included, or a no-argument call to `list`, `dict`, `set`, `tuple`, `frozenset`, `str` or `bytes`; an absence assertion is `assert not x` or one `==` or `is` comparison with an absent value on either side; an existence assertion is a bare name, attribute or subscript, a call to `isinstance`, `issubclass`, `callable`, `hasattr`, `bool` or `len`, one `is not` or `!=` comparison with an absent value on either side, `> 0`, `>= 1`, `0 <` or `1 <=`, an `in` whose right side calls `keys`, `vars` or `dir`, or `type(x)` compared with `==` or `is`; a tuple assertion is read pair by pair and is of a kind when every pair is; a test fails when it has an `assert`, every `assert` it has is of these kinds, and it holds no `raises`, `warns` or `deprecated_call` context and no call to an `assert*` method;
  - no clock reads and no sleeps: a test file fails that calls the `sleep` of `time`, `asyncio`, `trio` or `anyio`, even with `0`, or calls `time.time`, `time.monotonic` or `time.perf_counter`, each with or without `_ns`, `datetime.datetime`'s `now`, `utcnow` or `today`, or `datetime.date.today`, under any name the file imports it by; a keyword argument or string dict key named `timeout`, `interval` or `delay`, or ending in `_` and one of them, given a number above 0 and under 0.5, and such a number as the timeout of `asyncio.wait_for` or `asyncio.timeout`, fail too, as does a timeout above 0 to a blocking `wait`, `join`, `result`, `communicate`, `subprocess.run`, `call`, `check_call`, `check_output` or `select`; a cap handed to `Command` or `python_module`, naming a clock function without calling it, as a seam's default, and `.sleep` on any other receiver pass; child code in a string, beyond every gate, is `test-reviewer`'s;
  - no skip, skipif or xfail: a test file fails that holds a `skip`, `skipif` or `xfail` mark in any form, as a decorator, in `pytestmark` or in `pytest.param(marks=...)`, a call to `pytest.skip`, `pytest.xfail` or `pytest.importorskip`, or a `unittest` `skip`, `skipIf`, `skipUnless` or `expectedFailure`;
  - no test with zero assertions, no `and`/`or` at an assertion's root, no assertion in a loop or inside `all()`/`any()`, no assertion outside a test: an assertion is an `assert` statement or a `with` whose item calls an attribute named `raises`; a test whose own body, outside nested functions, holds none fails; an `assert` whose condition, under any leading `not`, is an `and` or `or` fails, and one nested deeper, as the operand of a comparison, passes; an assertion inside a `for` or `while` of the test fails, and so does an `assert` whose condition, under any leading `not`, is a call to `all` or `any`; an assertion anywhere in a test file outside a test's own body, at module level, in a helper, a fixture, a class or a function nested in a test, fails;
  - no multi-word string literal in an assertion unless the test seeded it: a literal is multi-word when it holds two alphabetic words of two or more letters joined by one space and none of `<`, `=`, `>`, `{` or `}`, and it is read in an `assert` condition and in `pytest.raises(match=...)`; the test seeded it when it appears verbatim in the test file outside an assertion, in a Python file under `tests/support/`, or as an argument the assertion hands to a call of a plain name, not of a method on the value under test; when it lies inside a longer seeded string or inside a file under `tests/support/fixtures/`; when it is seeded strings joined only by whitespace or punctuation; or when it fully matches an f-string with a multi-word part, in the test file or under `tests/support/`, each hole standing for any text;
  - no read of the host: a test file fails that calls `socket.gethostname`, `socket.getfqdn`, `platform.node`, `platform.uname`, `os.uname`, `os.getcwd`, `os.getcwdb`, `pathlib.Path.cwd`, `pathlib.Path.home`, `os.path.expanduser` or any `expanduser`, `os.getenv`, `os.getenvb`, any function of `locale`, `time.localtime`, `time.mktime`, `time.ctime` or an `astimezone` with no argument; that reads `os.environ`, `os.environb`, `time.tzname`, `time.timezone`, `time.altzone` or `time.daylight`; or that hands a port constant from 1 to 65535 to `bind`, `connect`, `connect_ex`, `create_connection`, `create_server`, `open_connection`, `start_server` or a name ending in `Server` or `Connection`;
  - no fake that computes its reply with own code: inside a function or class whose name, leading underscores dropped, starts with `fake` or `Fake`, a call into own code whose last name starts with a lower-case letter or `_` fails, and constructing an own class passes;
  - no route around an assert: a test file fails that raises `AssertionError`, calls `pytest.fail`, `typing.cast` or `typing_extensions.cast`, holds an `or` whose last operand is an absent value, or holds a `# type: ignore` comment with no error code or with `union-attr`.

  filepawl's `length`, `dircount` and `nesting` gates are off. Of its `snapshots` and `test-names` gates only the parts that count nothing are on: a test fails whose `assert` compares with `==` against a read of a golden file, an `open`, `read_text` or `read_bytes` whose arguments or receiver mention `__file__`, `importlib.resources` or a module-level name whose value mentions `__file__`, or a name the test assigned such a read before the `assert`, or against the `snapshot` fixture or an expression rooted at it, and a file the test's own run wrote and reads back from a temporary directory is not a golden file; a test fails whose name's last word, split on `_`, is all digits. How large a compared literal is and how vague a test name is go to `test-reviewer`. A finding names the test file and the test, function or module level it is in.

### Structure

- **Layering** with import-linter, exhaustive: every module under `gauntlet/` belongs to a contract. `seams` may import `core`; `core` may not import `seams`. `exclude_type_checking_imports = false`. `gauntlet` holds the packages `core` and `seams` and no other module, and `gauntlet/__init__.py` imports neither. An import counts whether it is direct or reaches the other layer through a chain of modules, and wherever it stands: at module level, in a function, or under `if TYPE_CHECKING:`. A finding names the contract, and the importing module, imported module and line of each import in the chain.
- **Pure core**: a `forbidden` contract stops `gauntlet.core` importing `os`, `sys`, `io`, `pathlib`, `subprocess`, `socket`, `shutil`, `tempfile`, `time`, `datetime`, `random`, `asyncio`, `threading`, `multiprocessing` or `logging`. A submodule counts as its module, as `os.path` does as `os`, and every spelling counts, `from os import path` and `import os as o` among them, whether the import is direct or goes through another module of `gauntlet.core`, under `if TYPE_CHECKING:` included.
- **filepawl code gates**: no re-export or forwarding modules, consistent key sets for dict returns, no `dict[str, Any]` results, no sentinel return from an `except`, no import of another module's private names. Each fails on:
  - a module whose body holds an import and defines nothing, an `__init__.py` included, where defining means a function, a class or a module-level assignment other than to `__all__`, and logic only under `if __name__ == "__main__":` defines nothing;
  - a function or method, at any depth, whose body after an optional docstring is one `return` of a call, through at most one `await`, to an attribute chain rooted at a plain name, passing exactly the function's positional parameters, in order, as bare names, with no keyword or starred argument, the first parameter spent on the chain when the chain is rooted at it;
  - a function whose `return` statements of dict literals with only string-constant keys carry more than one key set, or carry one key set with some key empty on one return and not on another, where empty is `None`, `""`, `b""`, an empty list, tuple, set or dict display, or a no-argument call to `list`, `dict`, `tuple`, `set`, `frozenset` or `str`; a dict with a `**` spread or a non-constant key, any other return value and a bare `return` are not read, and a nested function's returns are its own;
  - a return annotation, a module-level alias (`X = ...` of a subscript, `|`, name or attribute, `X: TypeAlias = ...`, or `type X = ...`, under a module-level `if TYPE_CHECKING:` included) or a field (an annotated name in a class body or an annotated `self.attr` in a function) whose type holds, anywhere and in string annotations too, a bare `dict`, `Dict`, `Mapping` or `MutableMapping`, or one whose value type is `Any` or `object` or a union with one among its members, the items of `Literal` aside; a field whose type, with `ClassVar`, `Final`, `Annotated`, `InitVar`, `Required`, `NotRequired` and `ReadOnly` taken off, is `Any`, `object` or a union with one among its members fails too, and `list[Any]` and `Callable[..., Any]` pass;
  - a function with a `return <value>` anywhere in an `except` or `except*` body, a bare `return` there while it returns a value elsewhere, or an assignment there to a plain name, a constant-key item or a plain-name attribute that one of its value returns reads directly; a nested function or lambda is judged on its own;
  - a `from` import, at any scope, of a private name, one that begins with `_` and is not a dunder, from own code or by a relative import, where the name is not itself a module of the tree.

  A finding names the file and the function, module or name it is about.
- **Dead code**: vulture over the whole tree with `min_confidence = 60`, no whitelist, no `ignore_names`, no `ignore_decorators`. A name only a test uses is used. A finding is one vulture report at confidence 60 or above and names the file, the line, the unused name or unreachable code, and vulture's confidence.

### Dependencies

- Every dependency is pinned to one version in a committed `uv.lock`: the runtime and dev dependencies, direct and transitive, and the build backend and every package it needs to build at an exact version as well. The gate fails when `uv.lock` is missing or not tracked by git, when the lock does not satisfy a dependency `pyproject.toml` declares, when the lock holds a package nothing in `pyproject.toml` needs, or when a build dependency has no exact version; a finding names the package and what is out of date.
- deptry fails on unused, missing or transitive-only dependencies. A dependency is used when a Python file imports it or when a gate, or the pre-commit hook, runs its command; a declared dependency nothing uses is a finding, a dev dependency included. A package imported only from `tests/` or `gates/` is declared in the dev group, one imported from `gauntlet/` in `[project] dependencies`, and one declared in the wrong place is a finding, as is a declared standard-library module. Own code needs no declaration. A finding names the package, the rule it breaks and, for a missing or transitive-only one, each file and line that imports it.

### Gate code

- Every gate script has its own tests, under every gate above. A gate script has its own tests when a test file imports it; the wiring check fails on one that no test file imports.
- A wiring check fails if a script in the gates directory is not invoked by `make check`. A script is invoked when the `check` target runs it over every Python file the tree holds; one the target runs over a subset, or only another target runs, is a finding. A module under `gates/` that the `Makefile` names nowhere is not a gate script and is exempt from the wiring check, but nothing imports it except gate scripts, the modules under `gates/core/`, Python files under `tests/support/` and its own tests; one that any other file imports, or that no test file imports, is a finding.
- A gate reads its checker's machine-readable output where the checker offers one, and a finding carries the checker's whole message.

## Judgment layer

A reviewer agent, defined in the repository, reads each diff without being told what it is for and returns findings anchored to file and line with a failure scenario. It looks for what no program can prove: incoherence, low cohesion, a duplicated concept, logic in the wrong home, a patch where a root-cause fix belongs. A finding stands until the code is fixed or the owner rules on it.

## Non-goals

- Mechanisms that stop an agent bypassing the gates (`--no-verify`, `SKIP=`, editing gate config).
- The gate that blocks shell-command parsing in Gauntlet's own code (roadmap M1).
- Gates for any language other than Python.

## Left to the builder

- Directory and file names for gate scripts.
