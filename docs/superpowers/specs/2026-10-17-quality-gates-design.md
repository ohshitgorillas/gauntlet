# Quality gates for building Gauntlet

Status: approved 2026-10-18.

## Intent

Gauntlet is built by agents before it can build itself. Gating is extremely strict and trust in agent-written code is low. The outcome wanted is coherent, cohesive, correct, easily testable code: no shortcuts, no patches, no workarounds. A small bug that shows a whole system is wrong leads to the system being rebuilt, not the symptom patched.

These gates go in before any product code. M1 starts under the full set.

## Principles

1. **A gate must be impossible to satisfy without the code getting better.** A gate an agent can pass by reshaping code, rather than improving it, is not included.
2. **No count caps.** Nothing triggers on a number of arguments, returns, branches, statements, lines, nesting levels, files per directory, or a complexity score. Whether a unit does too much is a question for the reviewer.
3. **No coverage threshold.** Test quality is judged by mutation testing. Coverage is measured only to find lines mutation testing cannot see.
4. **No suppressions.** No inline suppression comment, no per-file ignore, no exemption table, no baseline, no ratchet. A finding is fixed in the code.

## Gates

All gates run from one entry point, `make check`, which pre-commit invokes. Every gate applies to every Python file in the tree: `gauntlet/`, `tests/`, gate scripts, and any hook or tool script. No path is excluded. A Python file is a file whose name ends in `.py` or `.pyi`, or an extensionless file whose first line is a shebang that names python; a `.pyw` file is not one. A gate's verdict on a Python file is the same whatever other files the tree holds. Every gate is a script under `gates/` that `make check` runs; a gate whose checker is an external tool runs that tool over the tree's Python files with the settings in `pyproject.toml`, which holds those settings and nothing else does, and returns the checker's findings. A gate exits 0 with no finding, 1 with one or more findings, and 2 when its checker could not finish; it prints each finding on its own line and prints its count line on every run. The count line of a run whose checker finished reads `<gate>: N finding(s) in M Python file(s)`, where `<gate>` is the name of the gate script without its extension and `finding(s)` and `file(s)` are printed as written whatever N and M are, and it is the last line the run prints. A Python file the checker cannot read or cannot parse is a file the checker did not finish: the gate prints what the checker reported for that file and exits 2, whatever it found in the other files. A gate given no Python file prints that nothing was checked and exits 1, since an empty run proves nothing.

A test file is a Python file under `tests/`, or a Python file named `conftest.py` wherever it sits. A test is a function whose name starts with `test`, at module level in a test file or as a method of a module-level class whose name starts with `Test`. Own code is the packages `gauntlet` and `gates`. A gate whose checker reads files other than Python files, such as `pyproject.toml`, `uv.lock` or the `Makefile`, still takes the tree's Python files, counts them as M in its count line, and exits 1 when given none. A gate changes no file it checks: it reports what a fix would be and applies none.

### Types

- mypy with `strict = true`, plus `warn_unreachable = true`, `disallow_any_explicit = true`, `disallow_any_expr = true`, and every optional error code in `enable_error_code`. `python_version = "3.12"`, `requires-python = ">=3.12"`, ruff `target-version = "py312"`.
- pyright in `strict` mode.
- `typing.cast` is banned (ruff `TID251`). The ban is on the function, not its spelling: it covers `typing.cast` under every name it is imported by, `typing_extensions.cast` included, and the banned-api table lists each such name.

### Lint and format

- ruff `select = ["ALL"]`, `preview` off. Every stable rule of the locked ruff runs except the `ignore` list below, and every other ruff option keeps its default save `target-version` and the banned-api table of Types; no pydocstyle `convention` is set, since one turns `D` rules off, and an option set otherwise is a finding. So `D104` holds for every `__init__.py`, an empty one included: every package carries a module docstring. A finding is one ruff diagnostic and names the file, line, column, rule code and ruff's message; a file with no diagnostic passes.
- `ignore` holds only:
  - `C901`, `E501`, `W505`, `PLR0911`, `PLR0912`, `PLR0913`, `PLR0915`, `PLR0917`;
  - `D203`, `D213`, `COM812`, `ISC001`;
  - `S603`.

  Each ignore carries a one-line reason comment in `pyproject.toml`. The reason is a `#` comment on the entry's own line, after the entry, and says why the rule is off; an entry with no comment there, or an empty one, is a finding.
- `per-file-ignores`: `tests/**` gets `S101` only. `tests/**` matches every file under `tests/` at any depth and nothing outside it.
- ruff format in check mode. A finding is one file the formatter would change, named by its path; a file it would leave as it is passes. The formatter runs with its defaults and the `target-version` above.

### Suppression gate

A gate script fails on any of the items below. The comment markers of the first two items are found by tokenizing and match only inside a comment token, never inside a string. A marker matches anywhere in the comment, ignoring case and the whitespace around the colon and between its words, so `#mypy:`, `# FMT: OFF`, `# type:ignore` and `x = 1  # note; fmt:skip` are each a finding. A marker needs no word boundary on either side, so `# notmypy: x` and `# fmt: offset` are each a finding too. A comment that carries more than one marker is one finding that names every marker it carries. A marker of the first item that contains a marker of the second, as `# pyright: ignore` contains `# pyright:`, carries both, and its comment is one finding naming both.

- a `noqa`, `type: ignore`, `pyright: ignore`, `pragma: no cover` or `pragma: no mutate` comment;
- a `# mypy:`, `# pyright:`, `# fmt: off` or `# fmt: skip` comment;
- a `@typing.no_type_check` decorator. The ban is on the function, not its spelling: it covers `typing.no_type_check` and `typing.no_type_check_decorator`, `typing_extensions` included, and any reference to either is a finding wherever it appears: imported, bound to another name, used as a decorator or called, so the import line and the assignment line are each a finding. Finding it takes a parse with the grammar of the pinned Python, 3.12, so a file the gate can tokenize but that grammar cannot parse, syntax added in 3.13 or later included, is a file the gate did not finish, and the gate exits 2 by the rule of the Gates intro. A parse that cannot run to its end, as when it runs out of depth or memory, is one the gate could not make, and its file is one the gate did not finish in the same way;
- a `per-file-ignores` entry other than `tests/** = ["S101"]`;
- an `ignore` entry not on the list above, or `preview` on;
- any mypy `[[tool.mypy.overrides]]` section, or a pyright rule downgraded from strict;
- any path excluded from a checker: ruff `exclude`/`extend-exclude`, mypy `exclude` or `follow_imports` other than `normal`, pyright `exclude`/`ignore`, coverage `omit`;
- any ignore list in another tool's config: mutmut `do_not_mutate`/`do_not_mutate_patterns`, import-linter `ignore_imports`, a filepawl exempt table or allowance baseline, a deptry ignore, a vulture whitelist, a pytest `filterwarnings` entry other than `"error"`, coverage `exclude_lines`/`exclude_also`;
- a pytest-timeout `timeout` mark in any form, a `conftest.py` that disables or unregisters a pytest plugin, or a pytest `addopts` entry that disables one.

### Tests

- **Mutation testing blocks.** mutmut runs over every Python file outside `tests/`, in full on every commit, with no cache. Any surviving mutant fails the gate. There is no score threshold. The fix is a test that kills the mutant, or deleting code no behavior depends on. An equivalent mutant means the code is rewritten. Each mutant runs against the whole suite under `tests/`, with the pytest settings below. A mutant is killed only when a test fails on it; one that survives, that no test executes, that outlasts mutmut's own time limit, or that mutmut marks suspicious or skipped is a finding, named as mutmut names it and carrying the change mutmut made. A run that leaves any mutant unchecked, or whose suite does not pass on the unmutated tree, is a run the checker did not finish. No result an earlier run left changes the verdict.
- **Seams:** tests use real git and filesystem. Podman and the Claude API never run in tests; seams take their process runner as a parameter. No test file imports `anthropic` or `claude_agent_sdk`, or any module under either, by any name. A test asserts the command a seam builds through a fake runner it hands the seam, and no test hands a command whose program is `podman` to anything that starts a process: `subprocess`, `os.system`, an `os.exec*`, `os.spawn*` or `os.posix_spawn*` function, or `asyncio.create_subprocess_exec` or `asyncio.create_subprocess_shell`.
- **No copy:** errors are typed exceptions carrying data; tests assert the type and the values they seeded. The gate for this is the last test-shape bullet below.
- **Unseen-line backstop.** A gate fails on any line in a file mutation testing covers that no test executes and on which mutmut generated no mutant, and lists each one. A line here is one coverage counts as a statement, and it is executed when any part of the test run, collection included, runs it. The files are every Python file outside `tests/`, as for mutation testing. A finding names the file and the line.
- **pytest strictness:** `--strict-markers`, `--strict-config`, `filterwarnings = ["error"]`, `xfail_strict = true`, random test order (pytest-randomly), and a per-test timeout of 30 seconds (pytest-timeout). The gate runs pytest under these settings over the test files among the Python files it is given: a file whose path as given has a `tests` directory component and whose name pytest collects by default, `test_*.py` or `*_test.py`, and any `conftest.py` beside one, so `tmp/tests/test_x.py` is one. Other given files are neither run nor counted, and a run given no such file checked nothing and exits 1. pytest takes its settings from the repository's `pyproject.toml` only; an ini file or `pyproject.toml` beside the test files is never read. The gate reads pytest's JUnit XML report and neither parses nor passes on pytest's console output. A failing test is one finding: a test whose call, setup or teardown fails, an `xfail` test that passes, a test that raises a warning and a test that runs past the timeout each fail. A finding is one line: the test's id, which is the test file's path as the gate was given it followed by `::Class::test` as pytest names them, then a colon, a space and the failure's `message` attribute from the report, every line break in it replaced by a space. In the count line N is the number of failing tests and M the number of test files run. Anything that stops pytest before or during collection is a run the checker did not finish, exit 2, with pytest's own error printed and the count line still printed: a collection error, an unknown marker under `--strict-markers`, a warning raised at collection, an unknown config key under `--strict-config`, a usage error, an internal pytest error, or no test collected from the test files given. pytest-randomly and pytest-timeout are active on every run: the gate passes pytest no option that disables a plugin and hands it an environment without `PYTEST_ADDOPTS` and `PYTEST_PLUGINS`. Each run takes a fresh random seed; before any finding the gate prints one line of its own, `<gate>: seed N`, with the seed pytest-randomly used, so a failing order can be run again. Besides that line, the findings and the count line, a finished run prints nothing. A `timeout` mark, a `conftest.py` that disables a pytest plugin and an `addopts` entry that disables one are suppressions, failed by the suppression gate.
- **Test-shape gates**, from filepawl's suite gates and hqptuner2's `check_test_assertions.py` and `check_no_copy_assertions.py`, applied to every test file:
  - no `unittest.mock`, `patch`, `monkeypatch` or `setattr` on code under test: a test file fails that imports `unittest.mock` or `mock` or any name from either, or names the `monkeypatch` or `mocker` fixture; so does a call to `patch` or to a chain ending `patch`, `patch.object`, `patch.dict` or `patch.multiple`, a call to any attribute named `setattr`, `delattr`, `setitem` or `delitem`, a builtin `setattr` or `delattr` on an imported name, an assignment, augmented assignment or `del` whose target is an attribute of an imported name, a `Mock`-family call with `spec` or `spec_set`, and any `create_autospec`, whatever each replaces; a collaborator's stand-in is a fake handed to the code as an argument;
  - no access to private names of the code under test: a private name begins with `_` and is not a dunder, and `_asdict`, `_replace`, `_fields`, `_field_defaults` and `_make` are public; a test file fails that reads or writes `x._name` where the test file does not itself define `_name` and `x` is not `self` or `cls`, that names such a name by string to `getattr`, `setattr`, `delattr`, `hasattr` or `patch.object`, or that imports own code through a module path with a private segment or imports a private name from it;
  - one claim per test: a test's claims are its `assert` statements at any depth of blocks, outside nested functions, lambdas and classes; `pytest.raises` and `pytest.warns` are not claims, an `==` between two tuple displays of equal length is one claim, and an `assert x is not None` or `assert isinstance(x, T)` whose `x` a later statement reads, followed by a later claim, is a narrowing guard and not a claim; a test with more than one claim fails;
  - no test that asserts only absence, or only existence or type: an absent value is `None`, `False`, `0`, `0.0`, `""`, `b""`, an empty list or dict display, a tuple display of absent values, the empty one included, or a no-argument call to `list`, `dict`, `set`, `tuple`, `frozenset`, `str` or `bytes`; an absence assertion is `assert not x` or one `==` or `is` comparison with an absent value on either side; an existence assertion is a bare name, attribute or subscript, a call to `isinstance`, `issubclass`, `callable`, `hasattr`, `bool` or `len`, one `is not` or `!=` comparison with an absent value on either side, `> 0`, `>= 1`, `0 <` or `1 <=`, an `in` whose right side calls `keys`, `vars` or `dir`, or `type(x)` compared with `==` or `is`; a tuple assertion is read pair by pair and is of a kind when every pair is; a test fails when it has an `assert`, every `assert` it has is of these kinds, and it holds no `raises`, `warns` or `deprecated_call` context and no call to an `assert*` method;
  - no clock reads and no sleeps: a test file fails that calls `time.sleep`, `asyncio.sleep`, `trio.sleep` or `anyio.sleep`, with `0` as much as any other argument, or calls `time.time`, `time.time_ns`, `time.monotonic`, `time.monotonic_ns`, `time.perf_counter`, `time.perf_counter_ns`, `datetime.datetime.now`, `datetime.datetime.utcnow`, `datetime.datetime.today` or `datetime.date.today`, under any name the file imports it by; a keyword argument or string dict key named `timeout`, `interval` or `delay`, or ending in `_` and one of them, given a number above 0 and under 0.5, and such a number as the timeout of `asyncio.wait_for` or `asyncio.timeout`, fail too; naming a clock function without calling it, as a seam's default, and `.sleep` on any other receiver pass;
  - no skip, skipif or xfail: a test file fails that holds a `skip`, `skipif` or `xfail` mark in any form, as a decorator, in `pytestmark` or in `pytest.param(marks=...)`, a call to `pytest.skip`, `pytest.xfail` or `pytest.importorskip`, or a `unittest` `skip`, `skipIf`, `skipUnless` or `expectedFailure`;
  - no test with zero assertions, no `and`/`or` at an assertion's root, no assertion in a loop or inside `all()`/`any()`, no assertion outside a test: an assertion is an `assert` statement or a `with` whose item calls an attribute named `raises`; a test whose own body, outside nested functions, holds none fails; an `assert` whose condition, under any leading `not`, is an `and` or `or` fails, and one nested deeper, as the operand of a comparison, passes; an assertion inside a `for` or `while` of the test fails, and so does an `assert` whose condition, under any leading `not`, is a call to `all` or `any`; an assertion anywhere in a test file outside a test's own body, at module level, in a helper, a fixture, a class or a function nested in a test, fails;
  - no multi-word string literal in an assertion unless the test seeded it: a literal is multi-word when it holds two alphabetic words of two or more letters joined by one space and none of `<`, `=`, `>`, `{` or `}`, and it is read in an `assert` condition and in `pytest.raises(match=...)`; the test seeded it when it appears verbatim in the test file outside an assertion, in a Python file under `tests/support/`, or as an argument the assertion hands to a call of a plain name, not of a method on the value under test; when it lies inside a longer seeded string or inside a file under `tests/support/fixtures/`; when it is seeded strings joined only by whitespace or punctuation; or when it fully matches an f-string with a multi-word part, in the test file or under `tests/support/`, each hole standing for any text;
  - no read of the host: a test file fails that calls `socket.gethostname`, `socket.getfqdn`, `platform.node`, `platform.uname`, `os.uname`, `os.getcwd`, `os.getcwdb`, `pathlib.Path.cwd`, `pathlib.Path.home`, `os.path.expanduser` or any `expanduser`, `os.getenv`, `os.getenvb`, any function of `locale`, `time.localtime`, `time.mktime`, `time.ctime` or an `astimezone` with no argument; that reads `os.environ`, `os.environb`, `time.tzname`, `time.timezone`, `time.altzone` or `time.daylight`; or that hands a port constant from 1 to 65535 to `bind`, `connect`, `connect_ex`, `create_connection`, `create_server`, `open_connection`, `start_server` or a name ending in `Server` or `Connection`;
  - no fake that computes its reply with own code: inside a function or class whose name, leading underscores dropped, starts with `fake` or `Fake`, a call into own code whose last name starts with a lower-case letter or `_` fails, and constructing an own class passes;
  - no route around an assert: a test file fails that raises `AssertionError`, calls `pytest.fail`, `typing.cast` or `typing_extensions.cast`, holds an `or` whose last operand is an absent value, or holds a `# type: ignore` comment with no error code or with `union-attr`.

  filepawl's `length`, `dircount` and `nesting` gates are off. Of its `snapshots` and `test-names` gates only the parts that count nothing are on: a test fails whose `assert` compares with `==` against a read of a golden file, an `open`, `read_text` or `read_bytes` whose arguments or receiver mention `__file__`, `importlib.resources` or a module-level name whose value mentions `__file__`, or a name the test assigned such a read before the `assert`, or against the `snapshot` fixture or an expression rooted at it, and a file the test's own run wrote and reads back from a temporary directory is not a golden file; a test fails whose name's last word, split on `_`, is all digits. How large a compared literal is and how vague a test name is go to `test-reviewer`. A finding names the test file and the test, function or module level it is in.

### Structure

- **Layering** with import-linter, exhaustive: every module under `gauntlet/` belongs to a contract. `seams` may import `core`; `core` may not import `seams`. `exclude_type_checking_imports = false`. `gauntlet` holds the packages `core` and `seams` and no other module, and `gauntlet/__init__.py` imports neither. An import counts whether it is direct or reaches the other layer through a chain of modules, and wherever it stands: at module level, in a function, or under `if TYPE_CHECKING:`. A finding names the contract, and the importing module, imported module and line of each import in the chain.
- **Pure core**: a `forbidden` contract stops `gauntlet.core` importing `os`, `sys`, `io`, `pathlib`, `subprocess`, `socket`, `shutil`, `tempfile`, `time`, `datetime`, `random`, `asyncio`, `threading`, `multiprocessing` or `logging`. A submodule counts as its module, as `os.path` does as `os`, and every spelling counts, `from os import path` and `import os as o` among them, whether the import is direct or goes through another module of `gauntlet.core`, under `if TYPE_CHECKING:` included.
- **filepawl code gates**: no re-export or forwarding modules, consistent key sets for dict returns, no `dict[str, Any]` results, no sentinel return from an `except`, no import of another module's private names. They read every Python file, test files included, and each fails on:
  - a module whose body holds an import and defines nothing, an `__init__.py` included, where defining means a function, a class or a module-level assignment other than to `__all__`, and logic only under `if __name__ == "__main__":` defines nothing;
  - a function or method, at any depth, whose body after an optional docstring is one `return` of a call, through at most one `await`, to an attribute chain rooted at a plain name, passing exactly the function's positional parameters, in order, as bare names, with no keyword or starred argument, the first parameter spent on the chain when the chain is rooted at it;
  - a function whose `return` statements of dict literals with only string-constant keys carry more than one key set, or carry one key set with some key empty on one return and not on another, where empty is `None`, `""`, `b""`, an empty list, tuple, set or dict display, or a no-argument call to `list`, `dict`, `tuple`, `set`, `frozenset` or `str`; a dict with a `**` spread or a non-constant key, any other return value and a bare `return` are not read, and a nested function's returns are its own;
  - a return annotation, a module-level alias (`X = ...` of a subscript, `|`, name or attribute, `X: TypeAlias = ...`, or `type X = ...`, under a module-level `if TYPE_CHECKING:` included) or a field (an annotated name in a class body or an annotated `self.attr` in a function) whose type holds, anywhere and in string annotations too, a bare `dict`, `Dict`, `Mapping` or `MutableMapping`, or one whose value type is `Any` or `object` or a union with one among its members, the items of `Literal` aside; a field whose type, with `ClassVar`, `Final`, `Annotated`, `InitVar`, `Required`, `NotRequired` and `ReadOnly` taken off, is `Any`, `object` or a union with one among its members fails too, and `list[Any]` and `Callable[..., Any]` pass;
  - a function with a `return <value>` anywhere in an `except` or `except*` body, a bare `return` there while it returns a value elsewhere, or an assignment there to a plain name, a constant-key item or a plain-name attribute that one of its value returns reads directly; a nested function or lambda is judged on its own;
  - a `from` import, at any scope, of a private name, one that begins with `_` and is not a dunder, from own code or by a relative import, where the name is not itself a module of the tree.

  A finding names the file and the function, module or name it is about.
- **Dead code**: vulture over the whole tree with `min_confidence = 60`, no whitelist, no `ignore_names`, no `ignore_decorators`. Every Python file is read, test files included, so a name only a test uses is used. A finding is one vulture report at confidence 60 or above and names the file, the line, the unused name or unreachable code, and vulture's confidence.

### Dependencies

- All dependencies pinned in a committed `uv.lock`; the gate fails if the lock is out of date with `pyproject.toml`. Every dependency is pinned to one version: the runtime and dev dependencies, direct and transitive, in `uv.lock`, and the build backend and every package it needs to build at an exact version as well. The gate fails when `uv.lock` is missing or not tracked by git, when the lock does not satisfy a dependency `pyproject.toml` declares, when the lock holds a package nothing in `pyproject.toml` needs, or when a build dependency has no exact version; a finding names the package and what is out of date.
- deptry fails on unused, missing or transitive-only dependencies. deptry reads every Python file, test files included. A dependency is used when a Python file imports it or when a gate, or the pre-commit hook, runs its command; a declared dependency nothing uses is a finding, a dev dependency included. A package imported only from `tests/` or `gates/` is declared in the dev group, one imported from `gauntlet/` in `[project] dependencies`, and one declared in the wrong place is a finding, as is a declared standard-library module. Own code needs no declaration. A finding names the package, the rule it breaks and, for a missing or transitive-only one, each file and line that imports it.

### Gate code

- Every gate script has its own tests, under every gate above. A gate script has its own tests when a test file imports it; the wiring check fails on one that no test file imports.
- A wiring check fails if a script in the gates directory is not invoked by `make check`. A script is invoked when the `check` target runs it over every Python file the tree holds; one the target runs over a subset, or only another target runs, is a finding. A module under `gates/` that the `Makefile` names nowhere is not a gate script and is exempt from the wiring check, but nothing imports it except gate scripts and its own tests; one that any other file imports, or that no test file imports, is a finding. A finding names the script.
- A gate reads its checker's machine-readable output where the checker offers one, and a finding carries the checker's whole message.

## Judgment layer

A reviewer agent, defined in the repository, reads each diff without being told what it is for and returns findings anchored to file and line with a failure scenario. It looks for what no program can prove: incoherence, low cohesion, a duplicated concept, logic in the wrong home, a patch where a root-cause fix belongs. A finding stands until the code is fixed or the owner rules on it.

## Non-goals

- Mechanisms that stop an agent bypassing the gates (`--no-verify`, `SKIP=`, editing gate config).
- The gate that blocks shell-command parsing in Gauntlet's own code (roadmap M1).
- Gates for any language other than Python.

## Left to the builder

- Directory and file names for gate scripts.
- How the unseen-line backstop joins coverage data with mutmut's mutant list.
- Parallelism of the mutation run, within half of `nproc`.
