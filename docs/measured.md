The last eight rows apply to image `ce3ff9524414`. The sidecar evidence covers a scratch proxy script on `python:3.13-slim`, no podman secret, a `python3` relay rather than `socat`, and one SELinux level; it establishes neither proxy-image behavior nor refusal of a mismatched level. SELinux denying `container_t` a connect to a socket held by an unconfined host process is an inferred cause of the socket refusal, without audit-log confirmation. The `:ro` result holds for the non-root user `--userns=keep-id` gives; a root process with `CAP_SYS_ADMIN` is outside it and is not how any kind runs. A copy of the CLI bound `:ro,z` from a scratch folder, labelled `container_file_t`, executes where the host's `data_home_t` original does not. The start time excludes `--rm` teardown and CLI start-up; its share of a job's wall clock requires the first job wall clock at M3.
